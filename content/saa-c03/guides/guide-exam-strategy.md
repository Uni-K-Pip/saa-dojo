SAA-C03 は、知識の量だけでなく「問題文の条件を正確に読み、いちばん合う設計を選ぶ」力を問う試験です。同じ知識を持っていても、時間配分と読み方しだいで得点が変わります。このガイドでは、本番で実力を出し切るための進め方をまとめます。

## 1. 試験の形式と採点のしくみ

| 項目 | 内容 |
|---|---|
| 問題数 | 65 問（採点対象 50 問と採点対象外 15 問。どれが採点対象外かは示されない） |
| 試験時間 | 130 分 |
| 形式 | 択一選択（正解 1 つと誤答 3 つ）、複数選択（5 つ以上の選択肢から正解 2 つ以上） |
| 結果 | 合格か不合格か。スコアは 100〜1,000 のスケールスコアで、合格は 720 以上 |
| 採点モデル | 補償型。ドメインごとの合格点はなく、試験全体で合格点に届けばよい |
| 未回答 | 不正解として採点される。推測で答えても減点はない |
| ドメインの比重 | ドメイン 1（セキュア）30%、ドメイン 2（弾力性）26%、ドメイン 3（高性能）24%、ドメイン 4（コスト最適化）20% |

この表から、次の 3 つの方針が決まります。

- **すべての問題に答えます。** 未回答は不正解になり、推測で答えても減点はありません。分からない問題も、消去法で絞ってから 1 つ選びます。
- **採点対象外の 15 問は見分けられません。** 見たことのない機能や極端に難しい問題が出ても、採点対象外かもしれないと割り切り、時間をかけすぎないようにします。
- **苦手なドメインがあっても合格できます。** 補償型なので、得意なドメインで取り返せます。ただし比重の大きいドメイン 1 とドメイン 2 を大きく落とすと、取り返すのは難しくなります。

> **ひっかけ注意**
> 720 点は「72% 正解すれば合格」という意味ではありません。スケールスコアは、難しさの少し違う複数の問題セットを公平に比べるための換算値で、正答率から単純には計算できません。練習では余裕を持って、初見の問題で 80% 以上を目標にします。

## 2. 時間配分

130 分で 65 問なので、1 問あたりの平均は 2 分です。1 周目を約 100 分で終え、残りの 30 分を見直しに使う計画にします。

| 経過時間 | 目安 |
|---|---|
| 30 分 | 20 問まで解き終える |
| 60 分 | 40 問まで解き終える |
| 100 分 | 65 問まで解き終える（1 周目の終わり） |
| 100〜125 分 | フラグを付けた問題を見直す |
| 125〜130 分 | 未回答の問題がないかを確認する |

時間を守るためのルールです。

- **1 問に 3 分以上かかりそうなら、いったん最善の答えを選び、フラグを付けて次へ進みます。** 空欄のまま進むと、時間切れのときに不正解が確定してしまいます。
- **長い問題文は、最後の一文（何を問われているか）から読みます。** 何を探しながら読めばよいかが分かり、読み直しが減ります。
- **30 分ごとに目安と比べます。** 問題の長さや難しさにはばらつきがあります。遅れていても焦らず、次の 30 分で少しずつ取り戻します。
- **体調も時間配分の一部です。** オンライン受験では途中で席を離れられず、休憩も取れません。テストセンターでは予定外の休憩が認められていますが、その時間も試験時間に含まれるものとして計画します。

> **試験のポイント**
> 英語で受験する英語ネイティブでない人は、受験の申し込み前に「ESL +30」を申請すると試験時間が 30 分延びます。日本語で受験する場合は対象外です。延長があるときは、上の目安を全体の時間に合わせて伸ばします。手続きは「受験の手続き」のガイドを参照してください。

## 3. 問題文の読み方

SAA の問題文は、たいてい次の順に書かれています。

1. **状況**: 会社や現在のシステムの説明（「オンプレミスで動いている」「Amazon EC2 で動かしている」など）
2. **要件**: 満たさなければならないこと（「〜する必要がある」「〜しなければならない」）
3. **制約**: 予算、期限、既存のシステム、規制など
4. **問い**: 制約語を含む最後の一文（「最もコスト効率が高いソリューションはどれですか」など）

読む手順は次のとおりです。

1. 最後の一文を読み、何を選ぶ問題か（サービス、構成、手順の組み合わせ）と、制約語を確かめます。
2. 本文から要件と制約を拾います。特に数値（RPO・RTO、レイテンシー、保存期間、データ量）と、「既存の」「変更せずに」「オンプレミス」のような前提を表す言葉に注意します。
3. 選択肢を読む前に、答えの方向を自分で考えます。例: 「処理を疎結合にしたい、順序も守りたい → Amazon SQS の FIFO キュー」。
4. 選択肢を読み、考えた方向と照らし合わせます。

### 制約語と選ぶべき設計の方向

| 制約語の例 | 最優先すること | 選ばれやすい設計 | 外れやすい設計 |
|---|---|---|---|
| 最もコスト効率が高い、最も安い | 費用 | 使った分だけの課金（サーバーレス）、合った購入オプション（スポットインスタンス、Savings Plans）、安いストレージクラスとライフサイクルルール | 常時動かす大きすぎる構成、要件にない冗長化 |
| 運用上のオーバーヘッドが最も少ない、管理の手間を最小限に | 運用負荷 | マネージドサービス、サーバーレス、AWS に組み込みの機能 | Amazon EC2 上での自前構築、自作のスクリプトや定期実行、手作業 |
| 高可用性、耐障害性 | 止まらないこと | 複数のアベイラビリティーゾーン（AZ）への配置、Amazon EC2 Auto Scaling、マルチ AZ 配置のデータベース、Amazon Route 53 のフェイルオーバー | 1 つの AZ やインスタンス 1 台だけの構成 |
| 最も高い性能、低レイテンシー | 速さ | キャッシュ（Amazon ElastiCache、DynamoDB Accelerator（DAX）、Amazon CloudFront）、リードレプリカ、合ったインスタンスタイプやボリュームタイプ | 毎回ディスクやデータベースを読む構成、遠いリージョンからの配信 |
| 最も安全、最小権限 | セキュリティ | IAM ロール、必要な操作だけを許すポリシー、暗号化、VPC エンドポイントなどのプライベートな接続 | コードへのアクセスキーの埋め込み、広すぎる権限、インターネット経由の通信 |
| 既存アプリケーションの変更を最小限に | 移行しやすさ | 互換性のあるマネージドサービス（同じエンジンの Amazon RDS、NFS で使える Amazon EFS など）、設定だけで済む機能 | アプリケーションの作り直し、データモデルの変更 |

> **試験のポイント**
> 「最も〜」は、要件をすべて満たす選択肢どうしを比べるための条件です。まず要件を 1 つでも満たさない選択肢を外し、残った中から制約語で 1 つに絞ります。どんなに安くても、要件を満たさない選択肢は正解になりません。

### 答えを左右しやすい言葉

| 問題文の言葉 | 考える方向 |
|---|---|
| 「既存の」「現在の」「変更せずに」 | 前提として変えてはいけないもの。互換性を優先する |
| 「予測できない」「急に増える」「季節によって変わる」 | 自動スケーリング、サーバーレス、オンデマンドの課金 |
| 「中断されてもよい」「再実行できる」「短期間」 | スポットインスタンス |
| 「1 年以上」「24 時間 365 日」「安定した負荷」 | Savings Plans やリザーブドインスタンス |
| 「ほぼリアルタイム」「ストリーミング」 | Amazon Kinesis Data Streams、Amazon Data Firehose |
| 「マイクロ秒」 | DynamoDB Accelerator（DAX） |
| 「数時間待てる」「ほとんど読まない」 | S3 Glacier Flexible Retrieval、S3 Glacier Deep Archive |
| 「グローバル」「世界中のユーザー」 | Amazon CloudFront、AWS Global Accelerator、グローバルな構成のデータベース |

## 4. 消去法

誤答の選択肢は「もっともらしいが、どこか 1 点が合わない」ように作られています。よくある外れ方は次の 5 つです。

| 外れ方 | 例 |
|---|---|
| 要件を 1 つ満たさない | 高可用性が必要なのに 1 つの AZ だけに置いている。暗号化の要件を満たしていない |
| その機能がない、またはその組み合わせでは動かない | サービスが持っていない機能を前提にしている。上限を超える使い方をしている |
| 手間がかかりすぎる | 組み込みの機能で済むのに、スクリプトを自作したり EC2 上で自前で運用したりしている |
| 過剰で高い | 要件にない冗長化や、常時動かす大きな構成を使っている |
| 問われていないことを解いている | 性能の改善を問われているのに、セキュリティの対策を答えている |

進め方は次のとおりです。

1. 明らかに外れている選択肢を消します。
2. 残った 2 つを並べ、**違う部分だけ**を比べます。共通する部分は正誤に関係ありません。
3. その違いが問題文のどの条件（要件・制約・制約語）に関わるかを探します。
4. 条件に合うほうを選びます。どちらとも決められないときは、制約語により合うほうを選び、フラグを付けます。

> **試験のポイント**
> 「AWS が用意している機能で解決できるのに、自作する選択肢」は、ほとんどの場合誤答です。特に「運用上のオーバーヘッドが最も少ない」と書かれた問題では、マネージドな機能を使う選択肢を優先します。

## 5. 複数選択問題

- **選ぶ数は問題文に書かれています**（「2 つ選択してください」など）。必ずその数だけ選びます。
- 部分点はないものと考え、全部の正解をそろえることを目指します。
- 選択肢を 1 つずつ独立に「正しい」「誤り」「分からない」に分けます。「正しい」が多すぎるときは、制約語にいちばん合わないものを外します。足りないときは、「分からない」の中から要件にいちばん近いものを選びます。
- 問われ方には 2 つの型があります。
  - **組み合わせ型**（「どの手順の組み合わせで要件を満たせますか」）: 選んだ選択肢を合わせて 1 つの構成になります。役割が重なっていないか、互いに矛盾していないかを確かめます。例えば、「S3 バケットへのアクセスを VPC 内からだけに限る」なら、「VPC エンドポイントを作る」と「そのエンドポイント経由のアクセスだけを許すバケットポリシーを書く」の 2 つで 1 つの構成になります。
  - **独立型**（「どのソリューションが要件を満たしますか」）: それぞれの選択肢が単独で要件を満たします。1 つずつ、それだけで要件を満たすかどうかを判定します。

## 6. 見直し

- **フラグは迷った問題にだけ付けます。** 2 つで迷った、条件を読み落としたかもしれない、時間切れで仮の答えにした、という問題が対象です。確信がある問題にまで付けると、見直しの時間が足りなくなります。目安は全体の 2 割（13 問ほど）までです。
- **見直しで答えを変えるのは、新しい根拠が見つかったときだけにします。** 読み落としていた条件に気づいた、別の問題を解いているうちに知識を思い出した、といった場合です。なんとなくの印象で変えると、正解を誤答に変えてしまうことがよくあります。
- **最後に未回答がないことを確かめます。** 試験の最後には、未回答やフラグ付きの問題を一覧で確認できます。終了の前に必ず見ます。

## 7. 日本語で受験するとき

日本語などの英語以外の言語で受験する人は、試験中に切り替えの機能（トグル）を使って、問題を英語で表示できます。次のようなときに使います。

- 日本語の文が不自然で、意味がはっきりしないとき
- サービス名や機能名が日本語に訳されていて、どの機能か分かりにくいとき
- 制約語の強さ（「最も」なのか「〜できる」なのか）や、否定の範囲を確かめたいとき

英語の問題文でよく使われる表現と、その意味です。

| 英語 | 意味 |
|---|---|
| MOST cost-effective | 最もコスト効率が高い |
| LEAST operational overhead | 運用上のオーバーヘッドが最も少ない |
| LEAST development effort | 開発の労力が最も少ない |
| MOST secure | 最も安全 |
| highly available | 高可用性 |
| fault tolerant | 耐障害性がある |
| with minimal changes | 変更を最小限に |
| near real time | ほぼリアルタイム |
| decouple | 疎結合にする |
| Select TWO. | 2 つ選択してください |

> **試験のポイント**
> 英語の表示は、迷ったときの確認手段として使います。全部の問題を両方の言語で読むと時間が足りなくなります。日本語で読んで意味がはっきりしない文だけ、英語で確かめます。

このアプリはサービス名を英語の正式名で書いています。練習の段階から、Amazon S3、AWS Lambda のような英語の名前で覚えておくと、英語の表示に切り替えたときにも迷いません。

## 8. 本番までの練習と当日の過ごし方

- **本番と同じ 65 問・130 分の模擬試験を、少なくとも 1 回は通しで解きます。** 2 時間以上集中し続ける感覚と、30 分ごとの進み具合を体で覚えます。
- **判断軸ドリルで、制約語から設計を選ぶ練習をします。** 「運用負荷が最小 → マネージド」のような対応が、考えなくても出てくるようにします。
- **間違えた理由を記録します。** 「読み落とし」が多いなら問題文の読み方を、「2 択で迷った」が多いなら比較早見表を見直します。
- **前日は新しいことを詰め込みません。** 比較早見表と、間違えた問題の要点を見直す程度にします。
- **当日は早めに準備します。** テストセンターには予約時刻の 15〜30 分前に着くようにします。オンライン受験は予約時刻の 30 分前から開始の手続きができ、途中で休憩できないので、始める前に用事を済ませておきます。

### 試験直前のチェックリスト

- 1 周目は約 100 分で終える計画を立てた
- 3 分以上かかる問題は、仮の答えとフラグを付けて先へ進むと決めた
- 制約語（コスト、運用負荷、可用性、性能、セキュリティ、変更最小）を見たら、まず印を付けるように読む
- 複数選択は、選ぶ数を確かめてから解く
- 最後に、未回答がないことを確かめる
