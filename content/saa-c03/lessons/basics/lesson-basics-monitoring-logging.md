システムは、作って終わりではありません。動いている様子を見張り、何が起きたかを記録しておくことで、障害にすぐ気づき、原因を調べ、不正な操作を見つけられます。このレッスンでは、AWS の監視とログの基本となる 3 つのサービスを学び、最後に基礎講座のまとめと、各ドメインのレッスンへの進み方を確認します。

## 基礎

### 3 つのサービスの役割

| サービス | 答えてくれる問い | 記録するもの |
|---|---|---|
| Amazon CloudWatch | 今、どのくらい元気に動いているか | メトリクス（CPU 使用率などの数値）とログ |
| AWS CloudTrail | だれが、いつ、何の操作をしたか | AWS の API の呼び出し（操作の記録） |
| AWS Config | リソースの設定はどうなっていて、いつどう変わったか。ルールに合っているか | リソースの設定とその変更の履歴 |

### Amazon CloudWatch

- **メトリクス**: リソースの状態を表す数値です。EC2 インスタンスの CPU 使用率やネットワークの通信量は、自動で集められます。EC2 の基本モニタリング（無料）では 5 分間隔、詳細モニタリング（有料）では 1 分間隔になります。メモリの使用率やディスクの空き容量は既定では集められないので、インスタンスに CloudWatch エージェントを入れて送ります。
- **アラーム**: メトリクスがしきい値を超えたときに動きます。Amazon SNS で通知したり、EC2 Auto Scaling で台数を増やしたり、EC2 インスタンスを再起動したりできます。
- **CloudWatch Logs**: アプリケーションや OS のログを集めて保存し、検索します。保存期間は自分で決められます。
- **ダッシュボード**: メトリクスのグラフを 1 つの画面にまとめて表示します。

### AWS CloudTrail

AWS CloudTrail は、AWS アカウントで行われた操作を記録します。マネジメントコンソール、AWS CLI、プログラムからの API の呼び出しのどれもが対象です。

- 既定で有効になっていて、「イベント履歴」で過去 90 日間の管理イベント（リソースの作成・変更・削除など）を無料で見られます。
- 90 日より長く残したいときは、「証跡（トレイル）」を作り、記録を S3 バケットに保存します。
- S3 のオブジェクトの読み書きのような「データイベント」は、イベント履歴には出ません。必要なら証跡で記録を有効にします。

### AWS Config

AWS Config は、リソースの設定と、その変化の履歴を記録します。例えば「先月の 1 日の時点で、このセキュリティグループはどのポートを開けていたか」を調べられます。

- **Config ルール**: 「S3 バケットを公開しない」「EBS ボリュームを暗号化する」などのルールを決めると、設定が変わるたびに評価し、違反しているリソースを「非準拠」として知らせます。違反を自動で直す設定（修復）もできます。

### そのほかの仕組み

- **VPC フローログ**: VPC の中のネットワークインターフェイスを出入りする IP の通信の情報を記録します。
- **AWS Health Dashboard**: AWS 側の障害や予定されたメンテナンスが、自分のリソースに影響するかを確認できます。

## 使い分け

| 知りたいこと | 使うもの |
|---|---|
| CPU 使用率が高くなったら知らせてほしい | CloudWatch アラームと Amazon SNS |
| アプリケーションのエラーのログを集めて検索したい | CloudWatch Logs |
| だれが EC2 インスタンスを削除したのかを調べたい | CloudTrail |
| セキュリティグループの設定が、いつどう変わったかを知りたい | AWS Config |
| 社内のルールに違反している設定のリソースを見つけたい | AWS Config ルール |
| どの IP アドレスから通信が来ているかを調べたい | VPC フローログ |

## 設計パターン

1. 重要なメトリクスに CloudWatch アラームを設定し、SNS でメールを送る。負荷の増加には Auto Scaling で自動的に対応する
2. CloudTrail の証跡をすべてのリージョンで有効にし、操作の記録を S3 に長期保存する
3. AWS Config で、公開設定や暗号化などの重要な設定を常に評価する

## 試験のポイント

> **試験のポイント**
> 「性能・状態の監視、アラーム」なら CloudWatch、「だれが何をしたか（API の操作の監査）」なら CloudTrail、「設定の変更履歴、ルールへの準拠の評価」なら AWS Config です。3 つの役割の違いは、ドメイン 1 と 2 で繰り返し問われます。

## ひっかけ注意

> **ひっかけ注意**
> EC2 インスタンスのメモリ使用率は、CloudWatch の既定のメトリクスにはありません。CloudWatch エージェントが必要です。

> **ひっかけ注意**
> CloudTrail のイベント履歴は 90 日分だけです。「1 年間の操作の記録を残す」なら、証跡を作って S3 に保存します。

## 基礎講座のまとめと次のステップ

SAA-C03 の試験は 130 分で 65 問（うち採点されるのは 50 問）、合格点は 1,000 点中 720 点です。問題は 4 つのドメインに分かれていて、基礎講座のレッスンは次のようにつながっています。

| ドメイン（比重） | 内容 | 土台になる基礎講座のレッスン |
|---|---|---|
| 1. セキュアなアーキテクチャの設計（30%） | IAM とアカウントの管理、ネットワークの防御、データの暗号化 | 責任共有モデル、IAM、IP アドレスとサブネット、DNS・HTTPS・ポート番号、暗号化 |
| 2. 弾力性に優れたアーキテクチャの設計（26%） | 疎結合、スケーリング、高可用性、災害対策 | グローバルインフラ、可用性とスケーラビリティ、疎結合とサーバーレス |
| 3. 高性能なアーキテクチャの設計（24%） | ストレージ、コンピューティング、データベース、ネットワーク、データの取り込みと分析 | ストレージの種類、データベースの種類、IP アドレスとサブネット、クラウドの基本と主要サービス |
| 4. コストを最適化したアーキテクチャの設計（20%） | ストレージ、コンピューティング、データベース、ネットワークのコスト | 料金の基本、ストレージの種類 |

次は、ロードマップからドメイン 1 のタスク 1.1 のレッスンに進みましょう。各ドメインのレッスンでは、この講座で学んだ用語を前提に、「どの設計を選ぶか」を問題文の制約語（コスト、運用負荷、可用性、性能、セキュリティなど）から判断する練習をします。迷ったときは、基礎講座の該当するレッスンに戻って確認してください。
