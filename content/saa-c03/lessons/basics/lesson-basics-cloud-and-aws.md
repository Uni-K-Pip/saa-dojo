基礎講座は、AWS を触ったことがない人が、試験の 4 つのドメインのレッスンに進むための準備をする講座です。最初のこのレッスンでは、「クラウドとは何か」と、これから何度も出てくる AWS の主要サービスの全体像をつかみます。

## 基礎

### まず知っておきたい IT の用語

| 用語 | 意味 |
|---|---|
| サーバー | ネットワーク経由で、ほかのコンピューターに機能やデータを提供するコンピューター。Web サイトを表示する Web サーバー、データを保存するデータベースサーバーなどがある |
| OS（オペレーティングシステム） | コンピューターを動かす基本ソフトウェア。Linux や Windows など |
| 仮想化・仮想マシン | 1 台の物理的なコンピューターの中に、ソフトウェアで複数の独立したコンピューター（仮想マシン）を作る技術 |
| データセンター | 大量のサーバーやネットワーク機器を、電源・空調・警備つきで運用する施設 |
| API | プログラムから機能を呼び出すための窓口。AWS の操作はすべて API の呼び出しとして実行される |

### オンプレミスとクラウド

自社でサーバーを買い、自社のデータセンターやサーバールームで動かす形を「オンプレミス」と呼びます。オンプレミスでは、機器の注文から設置まで数週間かかり、何年分の利用を見込んで先に購入するため、予想が外れると機器が余ったり足りなくなったりします。

AWS は、クラウドコンピューティングを「IT リソースをインターネット経由でオンデマンドに提供し、従量課金で支払うこと」と説明しています。次の 3 つの言葉が基本です。

- **オンデマンド**: 必要になったときに、必要な分だけ、数分で使い始められる
- **従量課金**: 初期費用なしで、使った分だけ支払う。不要になれば止めて支払いも止まる
- **伸縮性（エラスティシティ）**: 需要に合わせてリソースを増やしたり減らしたりできる。ピークに合わせて先に買っておく必要がない

### クラウドの 6 つのメリット

AWS の概要ホワイトペーパーは、クラウドのメリットを次の 6 つにまとめています。

| メリット | 意味 |
|---|---|
| 固定費を変動費に変える | 先にデータセンターやサーバーへ大きく投資せず、使った分だけ支払う |
| 規模の経済の恩恵を受ける | 多くの利用者の需要がまとまるため、自前で用意するより安い単価で使える |
| キャパシティの予測が不要になる | 必要な分だけ使い、数分で増減できる |
| スピードと俊敏性を高める | 新しいリソースを数週間ではなく数分で用意でき、試行錯誤しやすい |
| データセンターの運用と保守にお金を使わない | サーバーの設置や電源の管理ではなく、自社の事業に集中できる |
| 数分で世界中に展開する | 世界各地のリージョンにすぐ展開でき、利用者の近くで低い遅延を実現できる |

### IaaS・PaaS・SaaS

クラウドのサービスは、利用者がどこまで管理するかによって 3 つに分けられます。

| 種類 | 提供されるもの | 利用者が管理するもの | 例 |
|---|---|---|---|
| IaaS（Infrastructure as a Service） | ネットワーク、仮想サーバー、ストレージなどの基本部品 | OS、ミドルウェア、アプリケーション、データ。管理の自由度が最も高い | Amazon EC2 |
| PaaS（Platform as a Service） | ハードウェアと OS を含む、アプリケーションを動かす環境 | アプリケーションとデータ | AWS Elastic Beanstalk |
| SaaS（Software as a Service） | 提供者が運用する完成したソフトウェア | 使い方とデータ | Web メールなど |

下の段ほど提供者が多くを管理し、利用者の手間は減りますが、細かい制御はしにくくなります。AWS には、データベースの OS やソフトウェアの更新を AWS が受け持つ Amazon RDS のように、管理の多くを任せられる「マネージドサービス」がたくさんあります。

## 使い分け

### AWS の主要サービスの地図

AWS にはとても多くのサービスがありますが、最初は次の表のサービスを押さえれば十分です。詳しくは基礎講座の後のレッスンと、各ドメインのレッスンで学びます。

| 分野 | サービス | ひとことで言うと |
|---|---|---|
| コンピューティング | Amazon EC2 | 数分で起動できる仮想サーバー。OS から上を自分で管理する |
| コンピューティング | AWS Lambda | サーバーを用意せずにコードを実行する。実行した分だけ課金 |
| ストレージ | Amazon S3 | ファイルを「オブジェクト」として、ほぼ無制限に保存する |
| ストレージ | Amazon EBS | EC2 インスタンスに接続して使うディスク |
| データベース | Amazon RDS | リレーショナルデータベースのマネージドサービス |
| データベース | Amazon DynamoDB | キーで高速に読み書きする NoSQL データベース。サーバーの管理が不要 |
| ネットワーク | Amazon VPC | AWS の中に作る、自分専用の仮想ネットワーク |
| ネットワーク | Elastic Load Balancing | 届いた通信を複数のサーバーに振り分ける |
| ネットワーク | Amazon Route 53 | ドメイン名を IP アドレスに変換する DNS サービス |
| ネットワーク | Amazon CloudFront | 世界中の拠点からコンテンツを配信する CDN |
| セキュリティ | IAM | だれが、どの AWS リソースに、何をしてよいかを管理する |
| 監視 | Amazon CloudWatch | リソースの数値（メトリクス）やログを集め、アラームを出す |

### AWS の操作方法

AWS は、ブラウザで操作する AWS Management Console、コマンドで操作する AWS Command Line Interface（AWS CLI）、プログラムから呼び出す API のどれでも操作できます。どの方法でも、内部では同じ API が呼ばれています。

## 設計パターン

### 典型的な Web アプリケーションの構成

主要サービスは、組み合わせて使います。よくある Web アプリケーションは次のような流れです。

1. 利用者がブラウザでドメイン名を入力すると、Amazon Route 53 が IP アドレスを返す
2. 通信は Elastic Load Balancing のロードバランサーに届き、複数の EC2 インスタンスに振り分けられる
3. EC2 インスタンス上のアプリケーションが Amazon RDS のデータベースを読み書きする
4. 画像などのファイルは Amazon S3 に置き、Amazon CloudFront で配信する
5. これらはすべて Amazon VPC の中、または VPC と組み合わせて動き、IAM で操作できる人を絞り、Amazon CloudWatch で監視する

サーバーの管理をさらに減らしたい場合は、EC2 の代わりに AWS Lambda、RDS の代わりに Amazon DynamoDB を使う「サーバーレス」の構成も選べます。

## 試験のポイント

> **試験のポイント**
> 「初期投資を避けたい」「需要が予測できない」「需要の増減が大きい」と書かれていたら、従量課金と伸縮性を生かす設計（必要なときだけ増やし、不要なら減らす）が答えの方向です。

> **試験のポイント**
> 「運用上のオーバーヘッドを最小にする」「サーバーを管理したくない」と書かれていたら、EC2 に自分でソフトウェアを入れるより、マネージドサービスやサーバーレスを優先します。逆に「OS を細かく設定したい」「独自のソフトウェアを入れたい」なら EC2 が候補です。

## ひっかけ注意

> **ひっかけ注意**
> クラウドは「使った分だけ支払う」仕組みなので、使っていないリソースを動かしたままにすると料金がかかり続けます。「クラウドに移せば必ず安くなる」わけではありません。

> **ひっかけ注意**
> マネージドサービスでも、利用者の仕事はなくなりません。だれにアクセスを許すか、データをどう守るかは利用者が決めます。この分担は、次の次のレッスン「責任共有モデル」で学びます。
