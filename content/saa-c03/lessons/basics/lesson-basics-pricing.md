AWS は使った分だけ支払う仕組みですが、「何に」「どの単位で」料金がかかるかを知らないと、思わぬ請求につながります。試験のドメイン 4（コストを最適化したアーキテクチャ）の土台として、料金の基本、データ転送の料金、EC2 の購入オプション、料金を管理するツールを学びます。

## 基礎

### 料金の 3 つの基本要素

AWS の料金を決める基本の要素は、次の 3 つです。

1. **コンピューティング**: サーバーなどを動かした時間（秒や時間の単位）
2. **ストレージ**: 保存したデータの量と期間（GB と月の単位）
3. **送信方向のデータ転送**: AWS から外へ送ったデータの量（GB の単位）

このほかに、リクエストの回数（S3 や Lambda など）に応じた料金がかかるサービスもあります。

### 止めると止まる料金、止めても続く料金

| リソース | 料金の単位 | 使っていないとき |
|---|---|---|
| EC2 インスタンス（オンデマンド） | 動いている時間 | 停止中はインスタンスの料金がかからない |
| EBS ボリューム | 確保した容量と期間 | インスタンスを停止しても、ボリュームを削除するまで料金がかかる |
| S3 | 保存量、リクエストの回数、送信したデータ量 | オブジェクトを削除するまで保存料金がかかる |
| Lambda | リクエストの回数と実行時間 | 実行しなければ処理の料金はかからない |
| NAT ゲートウェイ | 動いている時間と処理したデータ量 | 削除するまで時間の料金がかかる |
| パブリック IPv4 アドレス（Elastic IP アドレスを含む） | 確保している時間 | 解放するまで料金がかかる |

### データ転送の料金

| 通信の向き | 料金 |
|---|---|
| インターネットから AWS へ（受信） | かからない |
| AWS からインターネットへ（送信） | かかる |
| 同じリージョンの別の AZ との間 | かかる（送る側と受ける側の両方に課金されるのが一般的） |
| 別のリージョンへ | 送る側のリージョンでかかる |
| 同じ AZ の中で、プライベート IP アドレスを使った EC2 インスタンスどうし | 通常かからない |

データ転送の料金はサービスによって例外があるので、正確な金額は各サービスの料金ページで確かめます。

### EC2 の購入オプション

| オプション | 内容 | 向いている使い方 |
|---|---|---|
| オンデマンドインスタンス | 長期の約束なしで、使った時間だけ支払う（秒または時間の単位） | 短期間の利用、需要が予測できない処理、まず試すとき |
| Savings Plans | 1 年か 3 年の間、1 時間あたりの利用金額を約束して割引を受ける。Compute Savings Plans は、EC2 のインスタンスファミリーやリージョンが変わっても適用され、Fargate と Lambda にも使える | 長期間、安定して使い続ける処理 |
| リザーブドインスタンス | 1 年か 3 年の間、インスタンスの種類などの条件を決めて予約し、割引を受ける | 構成が決まっていて、長期間動かし続けるサーバー |
| スポットインスタンス | AWS の余っている容量を、オンデマンドより大幅に安く（最大 90% 引き）使う。AWS が容量を必要とすると、2 分前の通知の後に中断される | 中断されてもやり直せる処理（バッチ処理、画像の変換、テスト） |
| Dedicated Hosts | 物理サーバーを 1 台まるごと専有する | 物理サーバーのソケットやコアの数で決まるソフトウェアのライセンスを持ち込みたいとき |

Savings Plans とリザーブドインスタンスは「約束」なので、実際に使わなかった分も支払います。

### 料金を管理するツール

| ツール | できること |
|---|---|
| AWS Cost Explorer | 料金と利用状況の推移をグラフで分析し、今後の見込みを予測する |
| AWS Budgets | 予算を決め、実際の料金や見込みが予算を超えそうなときに通知する |
| AWS Cost and Usage Report | 料金と利用状況の、最も詳しい明細を出力する |
| コスト配分タグ | リソースに付けたタグ（部署名やプロジェクト名など）ごとに料金を集計する |

## 使い分け

| 状況 | 選ぶもの |
|---|---|
| 24 時間動き続ける本番のサーバーを、少なくとも 1 年は使う | Savings Plans、リザーブドインスタンス |
| 数日だけの検証や、一時的に増えた需要 | オンデマンドインスタンス |
| 途中で止まっても再実行できるバッチ処理を、できるだけ安く動かす | スポットインスタンス |
| 予算の超過を早く知りたい | AWS Budgets |
| どのサービスの料金が増えているかを調べたい | AWS Cost Explorer |

## 設計パターン

- **購入オプションを組み合わせる**: 常に必要な台数は Savings Plans で割引を受け、需要が増えたときだけ増える分はオンデマンドやスポットで動かします。
- **使わない時間は止める**: 開発用やテスト用のサーバーは、夜間や週末に停止します。
- **データ転送の料金を減らす**: 画像などの静的なファイルは Amazon CloudFront で配信します。プライベートサブネットから S3 や DynamoDB にアクセスするなら、追加料金のかからないゲートウェイ型の VPC エンドポイントを使うと、NAT ゲートウェイのデータ処理料金を避けられます（ドメイン 4 で学びます）。

## 試験のポイント

> **試験のポイント**
> 「処理が中断されても問題ない」「最もコスト効率が高い」と書かれていたらスポットインスタンス、「1 年以上、安定して動かし続ける」なら Savings Plans かリザーブドインスタンス、「期間が短い」「中断できない」「需要が予測できない」ならオンデマンドインスタンスです。

> **試験のポイント**
> 「予算を超えそうになったら通知したい」なら AWS Budgets、「料金の傾向を分析したい」なら AWS Cost Explorer です。

## ひっかけ注意

> **ひっかけ注意**
> EC2 インスタンスを停止しても、接続している EBS ボリュームの料金はかかり続けます。不要になったボリュームやスナップショットは削除します。

> **ひっかけ注意**
> スポットインスタンスは中断されることがあります。止められないデータベースや、途中から再開できない長い処理には向きません。

> **ひっかけ注意**
> インターネットからのデータの受信は無料ですが、送信は有料です。また、同じリージョンの中でも、AZ をまたぐ通信には料金がかかります。
