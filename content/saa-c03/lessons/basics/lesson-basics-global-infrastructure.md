AWS のサービスは、世界各地にあるデータセンターで動いています。どこに何を置くかは、障害への強さ、通信の速さ、法令への対応に直結します。このレッスンでは、リージョン、アベイラビリティーゾーン（AZ）、エッジロケーションの 3 つを学びます。

## 基礎

### リージョン

リージョンは、AWS がデータセンターを集めて運用している、世界の地理的な地域です。日本には、アジアパシフィック（東京）リージョン（`ap-northeast-1`）と、アジアパシフィック（大阪）リージョン（`ap-northeast-3`）があります。

- 各リージョンは、ほかのリージョンから切り離されるように設計されています。あるリージョンで問題が起きても、ほかのリージョンに広がりにくくなっています。
- ほとんどのリソースは、作ったリージョンの中にだけ存在します。AWS がデータを勝手にほかのリージョンへ複製することはありません。複製したいときは、利用者が設定します。
- 使えるサービスや料金は、リージョンによって違うことがあります。

### アベイラビリティーゾーン（AZ）

アベイラビリティーゾーン（AZ）は、リージョンの中にある、互いに独立した場所です。

- 1 つの AZ は、1 つ以上のデータセンターでできていて、電源・ネットワーク・接続がそれぞれ冗長化されています。
- AWS の説明では、各リージョンは物理的に離れた 3 つ以上の AZ で構成されます。
- AZ どうしは何 km も離れていますが、互いに 100 km 以内にあり、低遅延・高帯域の専用回線で結ばれています。AZ 間でデータを同期的に複製できるほどの速さです。
- 物理的に離れているので、火災や洪水が起きても、影響を受けるのは 1 つの AZ だけになるように作られています。

AWS は、アプリケーションを複数の AZ に配置することをベストプラクティスとしています。1 つの AZ に障害が起きても、ほかの AZ で動き続けられるからです。

### エッジロケーション

エッジロケーションは、世界中の多くの都市に置かれた、利用者に近い拠点です（PoP とも呼びます）。数はリージョンよりずっと多く、主に次のサービスが使います。

- **Amazon CloudFront**: コンテンツのコピー（キャッシュ）を利用者の近くから返し、表示を速くする
- **Amazon Route 53**: ドメイン名の問い合わせ（DNS）に応答する
- AWS WAF、AWS Shield など、エッジで通信を守るサービス

エッジロケーションは、EC2 インスタンスなどを自由に起動する場所ではありません。特定のサービスが、利用者に近い場所で処理するために使う拠点です。

### そのほかの拠点

| 拠点 | 内容 |
|---|---|
| Local Zones | リージョンを拡張し、大都市の近くでコンピューティングやストレージを提供する。遅延を小さくしたいときに使う |
| Wavelength Zones（AWS Wavelength） | 通信事業者の 5G ネットワークの端に、AWS のコンピューティングとストレージを置く |
| AWS Outposts | AWS のインフラとサービスを、自社のデータセンターなどに設置する |

## 使い分け

### リソースの範囲

AWS のリソースには、「どの範囲に属するか」があります。

| 範囲 | 意味 | 例 |
|---|---|---|
| グローバル | 特定のリージョンに属さない | IAM のユーザーやロール、Amazon Route 53、Amazon CloudFront |
| リージョン | 1 つのリージョンに属し、その中の複数の AZ を使える | Amazon VPC、Amazon S3 のバケット（名前は全世界で一意） |
| AZ | 1 つの AZ に属する | サブネット、EC2 インスタンス、EBS ボリューム |

例えば、EBS ボリュームは同じ AZ にある EC2 インスタンスにしか接続できません。別の AZ で使うには、スナップショット（バックアップ）から新しいボリュームを作ります。

### リージョンの選び方

リージョンは、主に次の 4 つの観点で選びます。

1. **法令・規制**: データを特定の国や地域の中に保管する必要があるか
2. **遅延**: 利用者の近くか
3. **サービス**: 使いたいサービスや機能が提供されているか
4. **料金**: 同じサービスでもリージョンによって料金が違う

## 設計パターン

| 目的 | 構成 |
|---|---|
| 1 つの AZ の障害に耐える | 2 つ以上の AZ に EC2 インスタンスを置き、Elastic Load Balancing で振り分ける（マルチ AZ） |
| リージョン全体に及ぶ大規模な災害に備える | 別のリージョンにデータを複製し、そこでも動かせるようにする（マルチリージョン） |
| 世界中の利用者に速く届ける | Amazon CloudFront で、エッジロケーションからコンテンツを配信する |

## 試験のポイント

> **試験のポイント**
> 「1 つの AZ が使えなくなっても動き続ける」「高可用性」と書かれていたら、複数の AZ に分けて配置する設計を選びます。「リージョン全体の障害」や「大規模な災害」に備えるなら、別のリージョンへの複製が必要です。

> **試験のポイント**
> 「データを国内に保管しなければならない」という要件は、リージョンの選択で満たします。データは、利用者が複製を設定しない限り、選んだリージョンから自動では出ていきません。

## ひっかけ注意

> **ひっかけ注意**
> 同じ AZ に何台もサーバーを並べても、その AZ 全体の障害には耐えられません。台数ではなく、AZ を分けることが大切です。

> **ひっかけ注意**
> マルチ AZ の構成にしても、別のリージョンへのバックアップにはなりません。AZ はすべて同じリージョンの中にあるからです。
