ストレージは、データを保存しておく場所です。AWS には多くのストレージサービスがありますが、データの扱い方によって「ブロック」「ファイル」「オブジェクト」の 3 種類に分けると整理できます。このレッスンでは、それぞれの特徴と代表的なサービスを学びます。

## 基礎

### ブロックストレージ

ブロックストレージは、データを決まった大きさの「ブロック」に分けて保存します。OS からはパソコンのハードディスクと同じ「ディスク」に見え、ファイルシステムを作って（フォーマットして）使います。細かい読み書きを速く処理できるので、OS の起動ディスクやデータベースに向いています。

- **Amazon EBS**: EC2 インスタンスに接続して使うボリュームです。インスタンスとは別に存在するので、インスタンスを停止してもデータは残ります。データは同じ AZ の中の複数のサーバーに自動で複製され、スナップショット（ある時点のバックアップ）を取れます。接続できるのは、同じ AZ にあるインスタンスです。ボリュームの種類には、SSD を使うもの（汎用の gp3 など）と、HDD を使うものがあります。
- **インスタンスストア**: EC2 インスタンスが動く物理サーバーに直接付いているディスクです。とても速いですが一時的な領域で、インスタンスを停止・休止・終了するとデータは消えます。キャッシュや一時ファイルに使います。

### ファイルストレージ

ファイルストレージは、フォルダーとファイルの階層でデータを管理し、ネットワーク経由で複数のサーバーから同時に使えます。社内の「共有フォルダー」と同じ考え方です。サーバーとの通信には、Linux では主に NFS、Windows では SMB というプロトコル（通信の決まり）を使います。

- **Amazon EFS**: Linux 向けのファイルストレージです（NFS）。ファイルの追加や削除に合わせて容量が自動で増減し、容量を事前に決める必要がありません。リージョン型のファイルシステムは、データを複数の AZ に保存し、多くの EC2 インスタンスから同時に使えます。Windows のインスタンスでは使えません。
- **Amazon FSx**: 用途に合わせて選べるファイルストレージです。Windows の共有フォルダー（SMB）として使える Amazon FSx for Windows File Server や、高性能計算向けの Amazon FSx for Lustre などがあります。

### オブジェクトストレージ

オブジェクトストレージは、データを「オブジェクト」という単位で保存します。オブジェクトは、データ本体、データの説明情報（メタデータ）、名前（キー）でできています。フォルダーの階層はなく、「バケット」という入れ物の中にキーで置きます（キーに「/」を入れて、フォルダーのように見せることはできます）。読み書きは、HTTP(S) の API で行います。

- **Amazon S3**: 代表的なオブジェクトストレージです。保存できる量に上限を気にする必要がなく、1 つのオブジェクトは最大 50 TB です。データの耐久性は 99.999999999%（9 が 11 個）になるように設計されています。画像や動画、バックアップ、ログ、分析用のデータの置き場所に使います。
- オブジェクトは、一部を書き換えるのではなく、オブジェクト単位で書き込む（置き換える）のが基本です。データベースのように細かい更新を繰り返す用途には向きません。
- ほとんど読まないデータは、S3 Glacier 系のストレージクラスに置くと安く保存できます（ドメイン 4 のレッスンで学びます）。

### 3 種類の比較

| 項目 | ブロック | ファイル | オブジェクト |
|---|---|---|---|
| データの単位 | ブロック | ファイルとフォルダー | オブジェクト（データ + メタデータ + キー） |
| 使い方 | OS がディスクとして使う | 複数のサーバーがネットワーク経由で共有する | HTTP(S) の API で読み書きする |
| 代表的なサービス | Amazon EBS、インスタンスストア | Amazon EFS、Amazon FSx | Amazon S3 |
| 向いている用途 | 起動ディスク、データベース | 共有フォルダー、コンテンツ管理 | 大量のファイルの保存、バックアップ、配信 |

## 使い分け

| 要件 | 選ぶもの |
|---|---|
| EC2 インスタンスの起動ディスクや、1 台のサーバーで動かすデータベース | Amazon EBS |
| 消えてもよい一時データを、とても速く読み書きしたい | インスタンスストア |
| 複数の Linux サーバー（複数の AZ を含む）で同じファイルを共有したい | Amazon EFS |
| Windows サーバーでファイルを共有したい（SMB） | Amazon FSx for Windows File Server |
| 大量のデータを安く、高い耐久性で保存し、Web から配信したい | Amazon S3 |
| 社内のサーバーから、AWS のストレージを使いたい | AWS Storage Gateway |

## 設計パターン

- **Web アプリケーション**: EC2 インスタンスの起動ディスクは EBS、利用者がアップロードした画像は S3 に保存します。複数のサーバーが同じファイルを直接読み書きする必要があるなら EFS を使います。
- **バックアップ**: EBS はスナップショットでバックアップします。AWS Backup を使うと、EBS、EFS、RDS などのバックアップを 1 か所でまとめて管理できます。

## 試験のポイント

> **試験のポイント**
> 「複数の EC2 インスタンスから、同じファイルシステムを同時にマウントしたい」と書かれていたら、Linux なら Amazon EFS、Windows（SMB）なら Amazon FSx for Windows File Server です。

> **試験のポイント**
> 「量が予測できない大量のデータを、低コストかつ高い耐久性で保存したい」と書かれていたら Amazon S3 です。

## ひっかけ注意

> **ひっかけ注意**
> インスタンスストアのデータは、インスタンスを停止・終了すると消えます。「インスタンスを停止してもデータを残す」必要があるなら EBS を選びます。

> **ひっかけ注意**
> EBS ボリュームは、別の AZ のインスタンスには接続できません。同じ AZ の複数のインスタンスに接続できる機能（Multi-Attach）もありますが、使えるボリュームの種類が限られ、一般的なファイル共有には使いません。複数の AZ のサーバーでファイルを共有するなら EFS です。

> **ひっかけ注意**
> Amazon EFS は Windows のインスタンスでは使えません。「Windows」と書かれていたら FSx for Windows File Server を選びます。
