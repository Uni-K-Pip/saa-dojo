Web サイトを開くとき、裏側では「ドメイン名を IP アドレスに変える（DNS）」「決まった手順で通信する（HTTP・HTTPS）」「通信を暗号化する（TLS）」「相手のどのプログラムと話すかを決める（ポート番号）」という仕組みが動いています。どれも AWS の設計問題に毎回のように出てくる基礎です。

## 基礎

### DNS（ドメインネームシステム）

人間は `www.example.com` のようなドメイン名を使いますが、通信には IP アドレスが必要です。ドメイン名を IP アドレスに変換する仕組みが DNS です。

1. ブラウザが、近くの DNS サーバー（リゾルバー）に「`www.example.com` の IP アドレスは？」と問い合わせる
2. リゾルバーは、ルートのサーバー、`.com` を管理するサーバーと順にたどり、そのドメインを管理する「権威 DNS サーバー」にたどり着く
3. 権威 DNS サーバーが IP アドレスを答え、リゾルバーはその答えを一定時間（TTL）覚えておく

Amazon Route 53 は、AWS の権威 DNS サービスです。ドメインごとの設定の入れ物を「ホストゾーン」と呼び、インターネット向けのパブリックホストゾーンと、VPC の中だけで使うプライベートホストゾーンがあります。

| レコード | 意味 |
|---|---|
| A | ドメイン名を IPv4 アドレスに対応付ける |
| AAAA | ドメイン名を IPv6 アドレスに対応付ける |
| CNAME | ドメイン名を、別のドメイン名の別名にする |
| MX | メールの宛先となるサーバーを示す |
| エイリアス（Route 53 独自） | ロードバランサーや CloudFront などの AWS リソースを指す。リソースの IP アドレスが変わっても自動で追従する |

### HTTP と HTTPS

HTTP は、ブラウザ（クライアント）と Web サーバーがやり取りするときの決まりです。クライアントが「リクエスト」を送り、サーバーが「レスポンス」を返します。レスポンスには結果を表すステータスコードが付きます。

| ステータスコード | 意味 | 例 |
|---|---|---|
| 2xx | 成功 | 200 OK |
| 3xx | 別の場所へ移動（リダイレクト） | 301 Moved Permanently |
| 4xx | クライアント側の誤り | 403 Forbidden（権限がない）、404 Not Found（見つからない） |
| 5xx | サーバー側の誤り | 500 Internal Server Error、503 Service Unavailable |

HTTP の通信は暗号化されていないため、途中で盗み見られたり書き換えられたりするおそれがあります。HTTP を TLS で保護したものが HTTPS です。

### TLS と証明書

TLS（Transport Layer Security）は、通信を保護する仕組みです。昔の名前から「SSL/TLS」とも呼ばれます。TLS は次の 3 つを実現します。

- **暗号化**: 通信の中身を第三者に読まれないようにする
- **改ざんの検知**: 途中で書き換えられていないことを確かめる
- **サーバーの認証**: 通信相手が本物のサーバーであることを「証明書」で確かめる

証明書は、認証局（CA）が「このドメイン名の持ち主はこのサーバーだ」と保証する電子的な証明書で、有効期限があります。AWS Certificate Manager（ACM）は、証明書の発行・保管・更新を引き受けるサービスです。Elastic Load Balancing や Amazon CloudFront などの連携サービスで使う証明書を追加料金なしで発行でき、ACM が発行した証明書は自動で更新されます。

### ポート番号

1 台のサーバーでは、複数のプログラムが同時に通信を待っています。どのプログラム宛ての通信かを示す番号がポート番号（0〜65535）です。IP アドレスが「建物の住所」なら、ポート番号は「部屋番号」にあたります。

| ポート | 用途 |
|---|---|
| 22 | SSH（Linux サーバーへのリモートログイン） |
| 3389 | RDP（Windows サーバーへのリモートデスクトップ） |
| 80 | HTTP |
| 443 | HTTPS |
| 53 | DNS |
| 3306 | MySQL（Amazon Aurora MySQL 互換を含む） |
| 5432 | PostgreSQL |

通信の方式には、届いたことを確かめながら確実に送る TCP と、確認を省いて軽く速く送る UDP があります。Web やデータベースの通信は TCP、DNS の問い合わせは主に UDP を使います。

## 使い分け

### ポートで通信を絞る: セキュリティグループとネットワーク ACL

VPC では、ポート番号と送信元を指定して通信を許可します。

| 項目 | セキュリティグループ | ネットワーク ACL |
|---|---|---|
| 適用先 | EC2 インスタンスなどのリソース | サブネット |
| ルール | 許可だけ（拒否のルールは書けない） | 許可と拒否 |
| 戻りの通信 | 自動で許可される（ステートフル） | 戻りも明示的に許可が必要（ステートレス） |
| 評価 | すべてのルールを見て判断 | 番号の小さいルールから順に、最初に一致したもので判断 |

- 新しく作ったセキュリティグループには受信のルールがなく、何も入ってこられません。送信は既定ですべて許可されています。
- セキュリティグループのルールでは、送信元に IP アドレスの範囲だけでなく、別のセキュリティグループも指定できます。
- AWS は、セキュリティグループを通信制御の基本とし、必要に応じてネットワーク ACL を追加の防御として使うことを勧めています。

## 設計パターン

### 3 層の Web アプリケーション

| 層 | セキュリティグループの受信ルール |
|---|---|
| ロードバランサー | 443（HTTPS）を `0.0.0.0/0`（インターネット全体）から許可 |
| アプリケーションの EC2 インスタンス | アプリケーションのポートを、ロードバランサーのセキュリティグループから許可 |
| データベース | 3306 を、アプリケーションのセキュリティグループから許可 |

- 利用者との通信は HTTPS にし、ロードバランサーに ACM の証明書を設定します。ロードバランサーが暗号を解いて（TLS の終端）、後ろのサーバーに渡します。
- Route 53 では、`www.example.com` も `example.com` も、エイリアスレコードでロードバランサーに向けられます。
- サーバーの管理用に 22 番や 3389 番を開ける場合は、社内の IP アドレスの範囲だけに絞ります。AWS Systems Manager の Session Manager を使えば、受信のポートを開けずにサーバーに接続できます。

## 試験のポイント

> **試験のポイント**
> 「ドメインの頂点（`example.com`）をロードバランサーや CloudFront に向けたい」と書かれていたら、Route 53 のエイリアスレコードです。CNAME レコードはドメインの頂点に作れません。

> **試験のポイント**
> 「データベースへの接続を、アプリケーションサーバーからだけに限定したい」と書かれていたら、データベースのセキュリティグループで、送信元にアプリケーションサーバーのセキュリティグループを指定します。IP アドレスで指定するより、サーバーが増えても設定を変えずに済みます。

## ひっかけ注意

> **ひっかけ注意**
> 「特定の IP アドレスからの通信を拒否したい」とき、セキュリティグループは使えません。拒否のルールが書けるのはネットワーク ACL です（HTTP の通信なら AWS WAF も使えます）。

> **ひっかけ注意**
> ネットワーク ACL はステートレスなので、受信を許可しても応答の送信が許可されていなければ通信は成り立ちません。セキュリティグループはステートフルなので、許可した通信の応答は自動で通ります。

> **ひっかけ注意**
> HTTPS が守るのは「通信の途中」のデータです。ディスクやデータベースに保存されたデータの暗号化は別に設定します。これは「暗号化の基礎」のレッスンで学びます。
