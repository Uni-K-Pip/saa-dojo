暗号化は、データが盗まれたり盗み見られたりしても、中身を読めないようにする仕組みです。AWS の試験では「保存時の暗号化」と「転送時の暗号化」を区別し、鍵をだれがどう管理するかを選ぶ問題がよく出ます。このレッスンでは、その考え方と AWS の主な機能を学びます。

## 基礎

### 暗号化と鍵

- **暗号化**: 元のデータ（平文）を、鍵を使って読めないデータ（暗号文）に変えること
- **復号**: 鍵を使って、暗号文を平文に戻すこと

暗号化の強さは、鍵の扱いで決まります。鍵が漏れれば、だれでも復号できてしまいます。

| 方式 | 仕組み | 特徴 |
|---|---|---|
| 共通鍵暗号（対称鍵暗号） | 暗号化と復号に同じ鍵を使う | 速い。大量のデータの暗号化に向く。代表は AES-256 |
| 公開鍵暗号（非対称鍵暗号） | 公開してよい「公開鍵」と、本人だけが持つ「秘密鍵」の組を使う | 鍵を安全に受け渡す問題を解ける。TLS では証明書の確認などに使い、データ本体は共通鍵暗号で暗号化する |

### 保存時の暗号化と転送時の暗号化

| 種類 | 守る場面 | 主な手段 |
|---|---|---|
| 保存時の暗号化（at rest） | ディスクやストレージに置かれているデータ | Amazon S3 のサーバー側の暗号化、Amazon EBS の暗号化、Amazon RDS の暗号化 |
| 転送時の暗号化（in transit） | ネットワークを流れているデータ | TLS（HTTPS）、VPN |

2 つは守る場面が違うので、片方を設定してももう片方の代わりにはなりません。「保存時も転送時も暗号化する」と書かれていたら、両方を設定します。

### 主なサービスの保存時の暗号化

| サービス | 保存時の暗号化 |
|---|---|
| Amazon S3 | 2023 年 1 月 5 日以降、新しくアップロードされるオブジェクトはすべて、S3 が管理する鍵による暗号化（SSE-S3）で自動的に暗号化される。追加料金はなく、無効にもできない。AWS KMS の鍵を使う SSE-KMS も選べる |
| Amazon EBS | ボリュームを作るときに暗号化を有効にするか、リージョンごとの「デフォルトで暗号化」を有効にする。ボリュームのデータ、インスタンスとの間で送受信されるデータ、スナップショットが暗号化される |
| Amazon RDS | DB インスタンスを作るときに暗号化を有効にする。ストレージ、ログ、自動バックアップ、リードレプリカ、スナップショットが暗号化される |
| Amazon DynamoDB | すべてのデータが常に暗号化される。使う鍵の種類を選べる |

### 鍵の管理: AWS KMS

AWS Key Management Service（AWS KMS）は、暗号化に使う鍵（KMS キー）を作成・管理するサービスです。

- KMS キーは、AWS KMS の中のハードウェアセキュリティモジュール（HSM）で守られ、暗号化されていない状態で外に出ることはありません。
- S3、EBS、RDS など多くのサービスと連携しています。
- だれが鍵を使えるかはキーポリシーと IAM ポリシーで決め、鍵を使った記録は AWS CloudTrail に残ります。
- 大きなデータは、まず「データキー」で暗号化し、そのデータキーを KMS キーで暗号化します。これをエンベロープ暗号化と呼びます。

| 鍵の種類 | 管理するもの | 利用者ができること | 料金 |
|---|---|---|---|
| AWS 所有のキー | AWS のサービス | 見ることも管理することもできない | 無料 |
| AWS マネージドキー | AWS のサービスが利用者のアカウントに作る（`aws/s3` など） | 見ることと使用の監査はできるが、ポリシーやローテーションは変えられない。毎年自動でローテーションされる | 月額料金なし（使用料はかかる場合がある） |
| カスタマーマネージドキー | 利用者 | キーポリシー、自動ローテーションの有効化、無効化、削除の予約などをすべて管理できる | 月額料金と使用料 |

### そのほかの鍵と秘密情報の管理

- **AWS CloudHSM**: 自分専用の HSM をクラウドで使うサービスです。鍵を自社だけで管理しなければならない、といった厳しい要件に使います。
- **AWS Secrets Manager**: データベースのパスワードや API キーなどの秘密情報を保存し、自動でローテーション（定期的な変更）できます。秘密情報をコードに書き込まずに済みます。
- **AWS Certificate Manager（ACM）**: TLS の証明書を発行・更新します（DNS・HTTPS のレッスンで学びました）。

## 使い分け

| 要件 | 選ぶもの |
|---|---|
| 手間をかけずに保存データを暗号化したい | 各サービスの既定の暗号化（SSE-S3、AWS 所有のキーなど） |
| 鍵の使用を監査したい、鍵を使える人を自分で決めたい | AWS KMS のカスタマーマネージドキー（S3 なら SSE-KMS） |
| 専用のハードウェアで、自社だけが鍵を管理したい | AWS CloudHSM |
| ネットワーク上のデータを守りたい | TLS（HTTPS）、VPN |
| データベースのパスワードを安全に保管し、定期的に変えたい | AWS Secrets Manager |

## 設計パターン

### 暗号化されていない RDS や EBS を暗号化する

RDS の DB インスタンスは、作った後に暗号化を直接有効にすることはできません。EBS の既存のボリュームも同じです。次の手順で、暗号化された新しいものに置き換えます。

1. スナップショット（その時点の完全なコピー）を取る
2. 暗号化を有効にしてスナップショットをコピーする（EBS は、スナップショットから暗号化したボリュームを作る）
3. 暗号化されたスナップショットから新しい DB インスタンスやボリュームを作り、アプリケーションの接続先を切り替える

新しく作るボリュームを必ず暗号化したいなら、EBS の「デフォルトで暗号化」をリージョンごとに有効にしておきます。

## 試験のポイント

> **試験のポイント**
> 「暗号鍵の使用を監査したい」「鍵へのアクセスを細かく制御したい」「鍵のローテーションを自社で管理したい」と書かれていたら、AWS KMS のカスタマーマネージドキーです。「運用の手間を最小にしたい」だけなら、サービスの既定の暗号化で十分なことが多いです。

> **試験のポイント**
> 「既存の暗号化されていない RDS の DB インスタンスを暗号化したい」と書かれていたら、スナップショットを暗号化してコピーし、そこから復元する方法が定番です。

## ひっかけ注意

> **ひっかけ注意**
> KMS キーを削除すると、その鍵で暗号化したデータは二度と復号できなくなります。そのため削除はすぐには実行されず、7〜30 日の待機期間（既定は 30 日）の後に行われます。迷ったら削除ではなく無効化します。

> **ひっかけ注意**
> S3 の既定の暗号化が始まる前からある、暗号化されていないオブジェクトは、自動では暗号化されません。暗号化するには、オブジェクトをコピーし直します。

> **ひっかけ注意**
> HTTPS で通信していても、保存されたデータは暗号化されません。逆に、保存時の暗号化をしても、通信の途中は守れません。
