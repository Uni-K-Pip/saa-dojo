サーバーレスとコンテナは、サーバーの管理を減らしながら、負荷に応じて自動で伸縮する構成を作るための中心的な技術です。このレッスンでは、AWS Lambda の性能に関わる設定、コンテナのオーケストレーション（Amazon ECS と Amazon EKS）、Fargate の位置づけを学びます。

## 基礎

### AWS Lambda

イベントをきっかけに関数を実行するサーバーレスのサービスです。

- **実行時間**: 1 回の実行は最大 15 分。
- **メモリ**: 128 MB〜10,240 MB。**CPU の能力はメモリの設定量に比例して割り当てられます**（1,769 MB で 1 vCPU 相当）。
- **エフェメラルストレージ**（/tmp）: 容量を別に設定できますが、CPU の能力は変わりません。
- **同時実行**: 呼び出しが増えると実行環境が自動で増えます。**予約された同時実行**は、関数が使う同時実行数の確保と上限を決めます。**プロビジョニングされた同時実行**は、初期化済みの実行環境を用意して、コールドスタートの遅延を減らします。
- **コンテナイメージ**: 最大 10 GB のコンテナイメージを関数として実行できます。

### コンテナのオーケストレーション

| サービス | 特徴 |
|---|---|
| Amazon ECS | AWS ネイティブのコンテナオーケストレーション。タスク定義でコンテナを定義し、サービスで台数を維持する |
| Amazon EKS | マネージドな Kubernetes。既存の Kubernetes のマニフェスト、Helm チャート、エコシステムをそのまま使える |
| AWS Fargate | ECS と EKS で使える、サーバーレスのコンピューティング。サーバー（ノード）の管理が不要 |

ECS／EKS の実行基盤（起動タイプ）には、**EC2**（自分でインスタンスを管理。GPU、特殊なインスタンスタイプ、きめ細かなコスト最適化に向く）と **Fargate**（管理不要）があります。

## 使い分け

### サービスの選び方

| 条件 | 選択 |
|---|---|
| 短時間のイベント駆動の処理 | Lambda |
| 15 分を超える、またはコンテナ化された処理、サーバー管理なし | Fargate（ECS または EKS） |
| 既存の Kubernetes の資産・知識を活かす | Amazon EKS |
| AWS ネイティブで、シンプルにコンテナを動かす | Amazon ECS |
| 特殊なインスタンスや細かな制御が必要 | ECS／EKS の EC2 起動タイプ |

### Lambda の性能のチューニング

- **CPU を多く使う処理が遅い**: メモリの設定量を増やすと、CPU の能力も増えて、実行時間が短くなる。実行時間が短くなれば、メモリ増加による単価の上昇を相殺できる場合もある。
- **コールドスタートの遅延が問題**: プロビジョニングされた同時実行を設定する。
- **同時に実行できる数を保証・制限したい**: 予約された同時実行を設定する。
- **最適なメモリ量の探索**: オープンソースの AWS Lambda Power Tuning や、AWS Compute Optimizer の推奨事項（x86_64 などの対象条件を満たす関数が対象）を使う。

## 設計パターン

### イベント駆動でコンテナを起動する

Amazon S3 にファイルが置かれたら、Amazon EventBridge のルールで、ECS の Fargate タスクを起動して処理する構成です。処理が 15 分を超えても動かせ、処理がない間は料金がかかりません。多数のファイルを順番に処理したいときは、SQS を間に置いて、ワーカーのタスクを増減させます。

### Lambda を起点にした疎結合

API Gateway → Lambda → DynamoDB のサーバーレス構成は、サーバーの管理がなく、リクエストに応じて自動でスケールします。

## 試験のポイント

> **試験のポイント**
> 「Lambda の処理が遅い、CPU を使う」はメモリを増やすことです。エフェメラルストレージの拡大や予約された同時実行では CPU は速くなりません。

> **試験のポイント**
> 「既存の Kubernetes のマニフェストや Helm をそのまま使う」は Amazon EKS です。

> **試験のポイント**
> 「15 分を超えるコンテナ処理をサーバー管理なしで」は Fargate です。

## ひっかけ注意

> **ひっかけ注意**
> プロビジョニングされた同時実行は、コールドスタートの遅延を減らす設定で、CPU を使う処理自体を高速にするものではありません。

> **ひっかけ注意**
> Fargate は実行基盤で、オーケストレーターではありません。ECS または EKS と組み合わせて使います。

> **ひっかけ注意**
> Lambda は常に安いわけではありません。常に高い使用率で動き続けるワークロードは、EC2 や Fargate のほうが安くなることもあります。
