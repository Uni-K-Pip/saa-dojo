データレイクは、さまざまな形式のデータを、そのままの形でまとめて保存しておく場所です。AWS では Amazon S3 を保存先にして、その上に「カタログ」「クエリ」「権限管理」「可視化」のサービスを組み合わせます。このレッスンでは、それぞれの役割と選び方を学びます。

## 基礎

### データレイクの全体像

| 役割 | サービス | ひとことで |
|---|---|---|
| 保存 | Amazon S3 | 容量無制限・低コストの保存先 |
| メタデータ（スキーマ） | AWS Glue Data Catalog | テーブルの定義を一元管理する |
| クエリ | Amazon Athena | S3 のデータに SQL。サーバーレス |
| 権限管理 | AWS Lake Formation | 列・行・セルの単位で権限を一元管理する |
| 可視化 | Amazon QuickSight | ダッシュボードを作って共有する BI |
| データウェアハウス | Amazon Redshift | 大量データの高速な集計・分析 |

### Amazon Athena

- S3 に置いたまま、標準 SQL でクエリするサーバーレスのサービスです。インフラの管理が要りません。
- 料金は、クエリでスキャンしたデータ量に応じてかかります。
- **スキャン量を減らす工夫**: パーティション分割（日付など）、列指向形式（Parquet、ORC）への変換、圧縮。
- テーブルの定義は、AWS Glue Data Catalog に登録します。

### Amazon QuickSight

サーバーレスの BI サービスです。Athena、Redshift、S3 など多くのデータソースに接続し、ダッシュボードをブラウザーやモバイルで共有できます。**SPICE** というインメモリのエンジンにデータを取り込めば、表示が速くなります。

## 使い分け

### Athena と Redshift

| 観点 | Athena | Redshift |
|---|---|---|
| 構成 | サーバーレス。データは S3 のまま | データウェアハウス（クラスターまたはサーバーレス） |
| 向く用途 | たまに実行するアドホックなクエリ | 頻繁で複雑な集計、多数の同時利用者 |
| 課金 | スキャン量 | 稼働時間や処理量 |

「たまにしか使わない」「S3 のデータを直接調べる」は Athena、「毎日多数のユーザーが複雑な集計を繰り返す」は Redshift が目安です。Redshift Spectrum を使えば、Redshift から S3 のデータにもクエリできます。

### アクセス制御の層

| 制御したい単位 | 使う仕組み |
|---|---|
| バケット、プレフィックス、オブジェクト | S3 バケットポリシー、IAM ポリシー |
| データベース、テーブル、列、行、セル | AWS Lake Formation |

S3 のポリシーでは、ファイルの中の列や行は制御できません。**列や行の単位で一元管理したい**場合は Lake Formation です。Lake Formation で付与した権限は、Athena、Redshift Spectrum、Amazon EMR、AWS Glue など、連携するサービスで共通に効きます。

## 設計パターン

### データレイクの基本構成

1. 生データを S3 に保存する（取り込みは Firehose や AWS DataSync など）
2. Glue のクローラーと ETL ジョブでスキーマを登録し、Parquet に変換、パーティション分割する
3. Lake Formation で、チームごとの列・行の権限を設定する
4. Athena でクエリし、QuickSight でダッシュボード化する

### 権限を分けるときの注意

チームごとにデータのコピーを作ると、元データの更新のたびにコピーを直す必要があり、管理が分散します。権限は **1 つのデータに対して Lake Formation で絞る** のが原則です。

## 試験のポイント

> **試験のポイント**
> 「S3 のデータにサーバーなしで SQL」は Athena、「ダッシュボードで可視化」は QuickSight、「列・行レベルの権限を一元管理」は Lake Formation です。3 つの役割を取り違えないようにします。

> **試験のポイント**
> Athena の料金やスピードを改善する選択肢では、パーティション分割、Parquet などの列指向形式、圧縮が正解になりやすいです。

## ひっかけ注意

> **ひっかけ注意**
> Athena はクエリのためのサービスで、ダッシュボードを共有する機能はありません。ダッシュボードが要件なら QuickSight です。

> **ひっかけ注意**
> S3 のバケットポリシーや ACL では、ファイルの中の列や行は制御できません。「列レベル」「行レベル」と書かれていたら Lake Formation です。

> **ひっかけ注意**
> 月に数回しか使わないクエリのために、Redshift のクラスターや EMR の常時起動のクラスターを用意すると、使わない時間も料金がかかります。
