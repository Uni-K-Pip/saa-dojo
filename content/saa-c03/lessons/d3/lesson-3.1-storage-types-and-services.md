ストレージ選びでは、種類と性能の2点が問われます。このレッスンでは、性能を決める設定（ボリュームタイプ、スループットモード、リクエストの分散など）を学びます。オンプレミスとつなぐストレージは別のレッスンで扱います。

## 基礎

| 種類 | 代表サービス | 特徴 |
|---|---|---|
| ブロック | Amazon EBS、インスタンスストア | OS からディスクとして使う。小さなランダム I/O が得意 |
| ファイル | Amazon EFS、Amazon FSx | NFS や SMB で複数のサーバーが共有する |
| オブジェクト | Amazon S3 | API でオブジェクト単位に読み書きする。容量を気にせず使える |

性能の指標は、**IOPS**（1 秒あたりの読み書きの回数。小さなランダム I/O で重要）と**スループット**（1 秒あたりの転送量。大きなファイルの順次処理で重要）です。

## Amazon EBS

EC2 インスタンスに接続するブロックストレージです。通常は 1 つのボリュームを同じ AZ の 1 台のインスタンスに接続し、インスタンスを停止してもデータは残ります。

| タイプ | 最大 IOPS | 最大スループット | 主な用途 |
|---|---|---|---|
| gp3（汎用 SSD） | 80,000 | 2,000 MiB/s | 汎用。起動ディスク、中規模のデータベース |
| gp2（汎用 SSD、旧世代） | 16,000 | 250 MiB/s | 既存環境。新規は gp3 |
| io2 Block Express（プロビジョンド IOPS SSD） | 256,000 | 4,000 MiB/s | 高 IOPS、一貫したミリ秒未満のレイテンシー、高い耐久性 |
| io1（プロビジョンド IOPS SSD） | 64,000 | 1,000 MiB/s | 持続的な IOPS が必要なデータベース |
| st1（スループット最適化 HDD） | 500 | 500 MiB/s | ビッグデータ、ログなど大きな順次 I/O |
| sc1（コールド HDD） | 250 | 250 MiB/s | アクセスの少ないデータを最も安く |

- **gp3** は、容量に関係なく 3,000 IOPS と 125 MiB/s が基本に含まれます。足りなければ、容量を増やさずに IOPS とスループットだけを追加で購入できます。gp2 は容量に比例して性能が決まる（1 GiB あたり 3 IOPS）ので、性能のために容量を増やす必要があります。
- **io2** は、プロビジョニングできる IOPS が 1 GiB あたり最大 1,000（io1 は 50）です。耐久性は 99.999% で、gp3 や io1 より高く設計されています。最大の性能は Nitro System ベースのインスタンスで出ます。
- **st1 と sc1** は起動ディスクにできず、小さなランダム I/O にも向きません。

性能を引き出す設定です。

- **Elastic Volumes**: 使用中のボリュームを、デタッチや再起動なしに、サイズの拡張、タイプの変更、IOPS やスループットの調整ができます。サイズは縮小できません。拡張後は OS でファイルシステムも広げます。
- **インスタンス側の上限**: インスタンスタイプごとに EBS の帯域や IOPS の上限があり、小さなインスタンスでは性能が出きりません。
- **スナップショットから作ったボリューム**: 各ブロックへの最初のアクセスで遅延が大きくなります。ファストスナップショットリストア（FSR）を有効にしたスナップショットから作ると、作成直後から全性能が出ます。
- **Multi-Attach**: 1 つの io1/io2 ボリュームを、同じ AZ の複数の Nitro ベースのインスタンスに接続できます。クラスター対応のファイルシステムか、アプリケーション側の書き込み制御が必要です。

## インスタンスストア

物理サーバーに直接付いたディスクで、追加料金はありません。起動時にだけ接続でき、付け替えられません。再起動ではデータが残りますが、**停止・休止・終了、ディスクの故障**で消えます。キャッシュや一時ファイル、複製済みのデータに向きます。

## Amazon EFS

Linux 向けの NFS のファイルシステムで、容量が自動で増減します。Windows のインスタンスは対象外です。

- **種類**: リージョン（推奨）は複数の AZ に保存し、AZ の停止に耐えます。One Zone は 1 つの AZ のみです。
- **ストレージクラス**: Standard、Infrequent Access（IA）、Archive。ライフサイクル管理で自動で移せます。
- **パフォーマンスモード**: General Purpose が既定で、AWS は常にこちらを推奨しています。Max I/O は旧世代でレイテンシーが大きくなります。
- **スループットモード**: スループット不足は、こちらを見直します。

| モード | 向くワークロード | 課金 |
|---|---|---|
| Elastic（推奨） | 負荷が変動して予測しにくい。平均がピークの 5% 以下 | 読み書きしたデータ量 |
| Provisioned | 必要量が分かっている。平均がピークの 5% 以上 | 設定したスループット |
| Bursting | 保存容量に比例した性能でよい | 保存容量に含まれる |

## Amazon FSx

| 種類 | プロトコル | 選ぶ場面 |
|---|---|---|
| FSx for Windows File Server | SMB | Windows のファイル共有。Active Directory と NTFS の権限。マルチ AZ あり |
| FSx for Lustre | Lustre（Linux、POSIX 準拠） | HPC や機械学習など速度重視の処理。S3 バケットとリンクできる |
| FSx for NetApp ONTAP | NFS、SMB、iSCSI、NVMe | NetApp の運用（SnapMirror、ONTAP の CLI）を維持して移す。自動階層化 |
| FSx for OpenZFS | NFS | オンプレミスの ZFS（スナップショット、クローン）を移す |

FSx for Lustre のスクラッチはデータを複製せず、短期の処理向けです。パーシステントは複製され、長く使えます。S3 とリンクすると、オブジェクトがファイルとして見え、最初のアクセスで内容が読み込まれます。

## Amazon S3 の性能設計

S3 はリクエスト数に応じて自動でスケールします。性能の目安は**プレフィックス単位**で、1 つあたり少なくとも毎秒 3,500 件の書き込み系（PUT/COPY/POST/DELETE）、または 5,500 件の読み取り系（GET/HEAD）です。プレフィックスの数に上限はありません。

| 課題 | 対策 |
|---|---|
| リクエスト数が多い | 複数のプレフィックスに分散して並列にアクセスする |
| HTTP 503（Slow Down） | スケール中の一時的な応答。SDK の再試行（指数バックオフ）を使い、負荷は段階的に上げる |
| 大きなオブジェクトのアップロード | マルチパートアップロード（100 MB 以上で推奨）。並列で送れ、失敗したパートだけ再送できる |
| 大きなオブジェクトのダウンロード | バイト範囲を指定して並列に取得する |
| 遠隔地からの転送 | S3 Transfer Acceleration（エッジロケーション経由） |
| 同じオブジェクトの繰り返し取得 | Amazon CloudFront などでキャッシュする |
| 1 桁ミリ秒のレイテンシー | S3 Express One Zone（ディレクトリバケット） |

Transfer Acceleration は、バケット単位で有効にして専用のエンドポイントを使います。バケット名は DNS 準拠でピリオドを含まないこと。S3 Express One Zone は 1 つの AZ に保存する高速なストレージクラスで、コンピューティングと同じ AZ に置くと最も速くなります。

## 使い分けと設計パターン

| 要件 | 選ぶもの |
|---|---|
| 1 台のインスタンスのデータベース、起動ディスク | EBS gp3 |
| 80,000 IOPS 超、または一貫したミリ秒未満のレイテンシー | EBS io2 |
| 消えてもよい一時データを最速で | インスタンスストア |
| 増え方が読めない Linux の共有ファイル | EFS（リージョン） |
| Windows の SMB 共有 | FSx for Windows File Server |
| S3 のデータを HPC や機械学習で高速に処理 | FSx for Lustre |
| 大量データの保存、配信、容量の自動拡張 | S3 |

- **Web アプリケーション**: 起動ディスクは gp3、画像は S3 に置き、配信は CloudFront でキャッシュします。
- **EC2 上の高負荷データベース**: まず gp3 に IOPS を追加し、足りなければ io2 にします。

## 試験のポイント

> **試験のポイント**
> 「サービスを止めずに EBS の容量や性能を変える」は Elastic Volumes です。gp2 から gp3 への変更もできます。

> **試験のポイント**
> 「負荷が変動し、使った分だけ払う」EFS は Elastic スループットです。「S3 で 503」はプレフィックスの分散と再試行、「遠隔地から大きなファイル」は Transfer Acceleration とマルチパートアップロードです。

## ひっかけ注意

> **ひっかけ注意**
> インスタンスストアは速くても永続的ではありません。停止・終了で消えるので、永続データには不向きです。

> **ひっかけ注意**
> EBS は容量を自動では拡張しません。自動で増やしたいなら EFS か S3 です。Multi-Attach は io1/io2 だけで、同じ AZ に限られます。

> **ひっかけ注意**
> EFS のパフォーマンスモードとスループットモードは別の設定です。EFS は NFS なので、Windows には FSx for Windows File Server を使います。

> **ひっかけ注意**
> S3 Express One Zone は 1 つの AZ のストレージで、ファイルシステムではありません。
