AWS には、仮想サーバー、バッチ処理、サーバーレス、コンテナなど、多くのコンピューティングサービスがあります。性能と伸縮性を重視した設計では、処理の特徴（実行時間、並列度、必要なリソース、管理の手間）に合うサービスを選ぶことが出発点です。このレッスンでは、主なサービスの特徴と使い分けを学びます。

## 基礎

### 主なコンピューティングサービス

| サービス | 特徴 | 向いている処理 |
|---|---|---|
| Amazon EC2 | 仮想サーバー。インスタンスタイプ、OS、ネットワークを細かく選べる | 細かい制御が必要な処理、常時稼働のアプリケーション、HPC |
| AWS Lambda | サーバーレス。イベントで起動し、1 回の実行は最大 15 分 | 短時間のイベント駆動の処理 |
| AWS Fargate | コンテナをサーバー管理なしで実行 | コンテナ化された処理、Lambda の時間制限を超える処理 |
| AWS Batch | ジョブキューとコンピューティング環境を管理するバッチ処理サービス | 大量のバッチジョブ、依存関係のあるジョブ |
| Amazon EMR | Spark、Hadoop、Hive などで大量データを分散処理 | ビッグデータの分析・変換 |

### EC2 のインスタンスタイプと配置

- **インスタンスファミリー**: 汎用（M、T）、コンピューティング最適化（C）、メモリ最適化（R、X）、ストレージ最適化（I、D）、高速コンピューティング（P、G など）。ボトルネックに合わせて選びます。
- **プレイスメントグループ**: インスタンスの物理的な配置の方針です。**クラスター**は 1 つのアベイラビリティーゾーン内に近接配置し、低レイテンシーで高いネットワーク性能が必要な HPC などに使います。**スプレッド**は障害の影響を分けるため、別々のハードウェアに分散します。**パーティション**は大規模な分散システム向けに、グループを分けて配置します。
- **Elastic Fabric Adapter（EFA）**: MPI を使う密結合の HPC で、OS をバイパスした低レイテンシー通信を実現するネットワークインターフェイスです。

## 使い分け

### バッチ処理と分散処理

| 条件 | 選択 |
|---|---|
| 独立した大量のジョブ、依存関係、再試行、Spot の活用 | AWS Batch |
| Spark や Hive で大量データを分散処理、クラスターの細かい制御 | Amazon EMR |
| 短時間（15 分以内）のイベント駆動の処理 | AWS Lambda |
| 密結合の並列計算（MPI） | EC2 のクラスタープレイスメントグループ＋EFA |

AWS Batch は、ジョブキューに送られたジョブの量と必要なリソース（vCPU、メモリ）に応じて、マネージド型のコンピューティング環境がインスタンス（Spot を含む）や Fargate の容量を自動で増減します。ジョブの依存関係と自動再試行も設定だけで指定できます。

### エッジでのコンピューティング

利用者に近い場所で処理すると、レイテンシーを下げ、オリジンの負荷を減らせます。

| サービス | 特徴 |
|---|---|
| CloudFront Functions | CloudFront のエッジで動く軽量な JavaScript。ビューアーリクエスト／レスポンスのみ。ミリ秒未満で動作し、URL の書き換えやヘッダーの操作に向く |
| Lambda@Edge | CloudFront のイベントで動く Lambda。ビューアーとオリジンの両方のイベントに対応し、より複雑な処理やネットワークアクセスが可能 |
| AWS Local Zones | 大都市の近くに置かれた AWS の拠点で、利用者に近い場所で EC2 などを実行 |
| AWS Wavelength | 5G ネットワークの内側でコンピューティングを実行 |
| AWS Outposts | AWS のインフラを自社の施設に設置 |

リクエストごとの単純な書き換え（パスの小文字化、リダイレクトなど）は、最も軽量で安価な CloudFront Functions が向いています。

## 設計パターン

- 夜間の大量ジョブ：AWS Batch のマネージド型のコンピューティング環境で Spot を使い、ジョブ定義で再試行と依存関係を指定する。
- 数十台で並列に計算する HPC：同じインスタンスタイプを、クラスタープレイスメントグループに配置し、EFA を有効にする。
- 世界中の利用者へのコンテンツ配信：CloudFront に、エッジでの軽量な処理を組み合わせる。

## 試験のポイント

> **試験のポイント**
> 「大量のバッチジョブ」「ジョブキュー」「依存関係」「再試行」は AWS Batch です。「Spark／Hadoop で大量のデータを分析」は EMR です。

> **試験のポイント**
> 「密結合の HPC」「ノード間の低レイテンシー」は、クラスタープレイスメントグループと EFA です。

> **試験のポイント**
> 「CloudFront のリクエストごとの軽量な書き換え」は CloudFront Functions、「より複雑な処理」は Lambda@Edge です。

## ひっかけ注意

> **ひっかけ注意**
> Lambda の 1 回の実行は最大 15 分です。それ以上かかる処理は、Batch や Fargate、EC2 を選びます。

> **ひっかけ注意**
> Amazon EMR は、コンテナ化された独立したジョブを流す用途ではありません。既存のコンテナを Spark に書き直すことになるなら、Batch のほうが合います。

> **ひっかけ注意**
> クラスタープレイスメントグループは 1 つのアベイラビリティーゾーン内の配置です。性能を優先する代わりに、障害の影響を受けやすくなります。
