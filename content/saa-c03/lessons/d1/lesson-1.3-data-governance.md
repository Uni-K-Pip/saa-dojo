どんなデータを、どこに、だれが見られる状態で持っているかを把握し、決まりどおりに守られていることを示せる状態を「データガバナンス」と呼びます。監査や規制への対応では、守っていることの証拠も求められます。このレッスンでは、データへのアクセスの管理、データの分類、コンプライアンスの確認に使う AWS のサービスを学びます。

## 基礎

### アクセスを制御する仕組み

AWS では、だれが何にアクセスできるかを、主に次のポリシーで決めます。

- **IAM ポリシー**: ユーザーやロールに付けて、何ができるかを決める
- **リソースベースのポリシー**: S3 のバケットポリシーや KMS のキーポリシーのように、リソースの側に付けて、だれがアクセスできるかを決める
- **SCP（サービスコントロールポリシー）**: AWS Organizations で、組織のアカウントが使える権限の上限を決める

どのポリシーでも、明示的な拒否（Deny）は許可より優先されます。

### 予防的な統制と発見的な統制

- **予防的な統制**: 望ましくない操作そのものを止める（SCP、IAM ポリシー、S3 ブロックパブリックアクセスなど）
- **発見的な統制**: 起きたことや今の状態を記録・評価して、問題を見つける（AWS Config、AWS CloudTrail、Amazon Macie など）

試験では、「操作を防ぎたい」のか、「違反を見つけて報告したい」のかで、選ぶサービスが変わります。

## 使い分け

### データガバナンスに使うサービス

| やりたいこと | サービス |
|---|---|
| S3 の機密データ（個人情報、クレジットカード番号など）を見つけて分類する | Amazon Macie |
| データレイクで、テーブルの列や行の単位までアクセスを絞る | AWS Lake Formation |
| リソースの設定がルールに準拠しているかを継続的に評価し、変更履歴を残す | AWS Config |
| だれが、いつ、どの API を呼び出したかを記録する | AWS CloudTrail |
| AWS の第三者監査レポート（ISO、PCI など）や AWS との契約を入手する | AWS Artifact |

### S3 のアクセス管理

- **S3 ブロックパブリックアクセス**: バケットやアカウントの単位で、パブリックなアクセスをまとめて禁止する
- **オブジェクト所有者の「バケット所有者の強制」**: ACL を無効にして、アクセスをポリシーだけで管理する（新しいバケットの既定の設定）
- **バケットポリシーの条件**: aws:SecureTransport で HTTPS を必須にする、aws:SourceVpce で特定の VPC エンドポイントからのアクセスだけを許可する、など

S3 のポリシーで制御できるのは、バケットやオブジェクトの単位です。1 つのファイルの中の列や行を隠すことはできないため、その要件には Lake Formation を使います。

### AWS CloudTrail の記録

| 種類 | 内容 | 既定 |
|---|---|---|
| 管理イベント | バケットの作成やポリシーの変更など、リソースを管理する操作 | 証跡で記録される |
| データイベント | S3 の GetObject や PutObject など、リソースの中のデータへの操作 | 記録されない（有効にすると追加料金がかかる） |

「どのオブジェクトをだれが読んだか」を記録したい場合は、データイベントを有効にします。ログが改ざんされていないことを示すには、ログファイルの整合性の検証を有効にします。CloudTrail は 1 時間ごとにダイジェストファイルを作成し、ログファイルが変更・削除されていないかを確かめられるようにします。

## 設計パターン

### 組織全体のコンプライアンスの評価

AWS Config のマネージドルールをまとめたコンフォーマンスパックを、AWS Organizations の組織全体にデプロイします。新しく組織に参加したアカウントにも自動でデプロイされます。AWS Config のアグリゲーターを使うと、複数のアカウントとリージョンの準拠状況を 1 か所で確認できます。非準拠のリソースは、AWS Systems Manager Automation のドキュメントを使った修復アクションで直すこともできます。

### 機密データの検出から対応まで

Amazon Macie を AWS Organizations の委任管理者アカウントから組織全体で有効にし、自動機密データ検出でバケットを継続的に評価します。検出結果は Amazon EventBridge に送られるので、通知や対応の自動化にもつなげられます。

### データレイクの権限の一元管理

AWS Lake Formation に S3 の場所を登録し、AWS Glue Data Catalog のテーブルに対する権限を Lake Formation で付与します。データフィルターで列レベル、行レベル、セルレベルのセキュリティを設定でき、Amazon Athena などの統合されたサービスがクエリのたびにその権限を適用します。

## 試験のポイント

> **試験のポイント**
> 「S3 にある個人情報を見つけたい」「機密データを分類したい」は Amazon Macie です。

> **試験のポイント**
> 「設定が準拠しているかを継続的に評価したい」は AWS Config、「だれが操作したかを調べたい」は AWS CloudTrail です。

> **試験のポイント**
> 「監査人に AWS のコンプライアンスレポートを提出したい」は AWS Artifact です。レポートは追加料金なしでダウンロードできます。

## ひっかけ注意

> **ひっかけ注意**
> Amazon GuardDuty は不審なアクセスなどの脅威を、Amazon Inspector はソフトウェアの脆弱性を見つけるサービスです。データの中身を調べて分類するのは Macie です。

> **ひっかけ注意**
> Macie は機密データを見つけて知らせるサービスで、アクセスを止める機能はありません。アクセスの制御は、IAM ポリシー、バケットポリシー、Lake Formation などで行います。

> **ひっかけ注意**
> CloudTrail の証跡は、既定では S3 のオブジェクトへのアクセス（データイベント）を記録しません。
