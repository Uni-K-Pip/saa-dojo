プライベートサブネットのサーバーから AWS のサービスを呼び出すときや、会社のデータセンターと AWS をつなぐときに、通信をインターネットに出さずに済ませたり、暗号化したりする方法を学びます。キーワードは「VPC エンドポイント」「Site-to-Site VPN」「Direct Connect」の 3 つです。

## 基礎

### AWS のサービスのエンドポイント

Amazon SQS や Amazon S3 などの AWS のサービスは、API のリクエストを受け付ける URL を持っています。これをサービスのエンドポイントと呼びます（例 `sqs.<リージョン>.amazonaws.com`）。標準のエンドポイント名はパブリック IP アドレスに解決されるため、プライベートサブネットのサーバーから呼び出すには、次のどちらかが必要です。

- **NAT ゲートウェイ**: 通信はインターネットへ出て、サービスのパブリックなエンドポイントに届きます。
- **VPC エンドポイント**: 通信は VPC から AWS のネットワークの中だけを通ってサービスに届きます。インターネットゲートウェイも NAT ゲートウェイも不要です。

### VPC エンドポイントの 2 種類

| 項目 | ゲートウェイ型 | インターフェイス型（AWS PrivateLink） |
|---|---|---|
| 対応するサービス | Amazon S3 と Amazon DynamoDB だけ | S3、DynamoDB を含む多くの AWS のサービスと、他社・自社のサービス |
| 仕組み | ルートテーブルにエンドポイント宛てのルートを追加する | サブネットにプライベート IP アドレスを持つネットワークインターフェイスを作る |
| 料金 | 追加料金なし | AZ ごとの時間料金と、処理したデータ量の料金 |
| オンプレミスや Transit Gateway 経由での利用 | できない | できる（Direct Connect や VPN 経由で到達できる） |
| アクセス制御 | エンドポイントポリシー | エンドポイントポリシーとセキュリティグループ |

インターフェイス型のエンドポイントで「プライベート DNS」を有効にすると、VPC の中では標準のエンドポイント名がエンドポイントのプライベート IP アドレスに解決されます。そのため、アプリケーションのコードや SDK の設定を変えずに、通信だけをエンドポイント経由に切り替えられます。プライベート DNS を使うには、VPC の DNS 解決と DNS ホスト名の属性を有効にしておきます。

### PrivateLink で自社のサービスを公開する

AWS PrivateLink は、AWS のサービスだけでなく、自社のサービスをほかの VPC やほかの AWS アカウントに公開するのにも使えます。サービスを提供する側は Network Load Balancer をサービスの前面に置いて「エンドポイントサービス」を作り、利用する側はインターフェイス型のエンドポイントを作って接続します。VPC 同士をまるごとつなぐ VPC ピアリングと違い、公開したサービスにだけ接続させられます。

### オンプレミスとの接続

| 方法 | 用途 | 経路 | 暗号化 |
|---|---|---|---|
| AWS Site-to-Site VPN | 拠点のネットワークと VPC をつなぐ | インターネット（Direct Connect 上にも構成できる） | IPsec で暗号化 |
| AWS Client VPN | 利用者一人ひとりの端末から VPC に接続する | インターネット | 暗号化 |
| AWS Direct Connect | 拠点と AWS を専用の回線でつなぐ | 専用回線（インターネットを経由しない） | 既定では暗号化されない |

- **Site-to-Site VPN**: AWS 側は仮想プライベートゲートウェイか Transit Gateway、拠点側はカスタマーゲートウェイ（自社のルーターなど）が終端です。1 つの接続に 2 本のトンネルがあり、両方を設定して冗長にします。インターネットがあればすぐに作れて、費用も抑えられます。
- **Direct Connect**: 帯域や遅延が安定します。AWS と直接契約する専用接続と、Direct Connect パートナーが提供するホスト型接続があります。物理的な回線の手配が必要なので、すぐには使い始められません。

Direct Connect では、接続先に応じて仮想インターフェイス（VIF）を作ります。

| 仮想インターフェイス | 接続先 |
|---|---|
| プライベート VIF | VPC（プライベート IP アドレスで接続） |
| パブリック VIF | Amazon S3 などの AWS のパブリックなサービス（パブリック IP アドレスで接続） |
| トランジット VIF | Direct Connect ゲートウェイを経由して Transit Gateway に接続し、複数の VPC とつなぐ |

## 使い分け

| 要件 | 選ぶもの |
|---|---|
| プライベートサブネットから S3・DynamoDB へ、追加料金なしでインターネットを経由せずに接続 | ゲートウェイ型エンドポイント |
| プライベートサブネットからそれ以外の AWS のサービスへ接続 | インターフェイス型エンドポイント |
| オンプレミスから Direct Connect 経由で S3 にプライベートに接続 | S3 のインターフェイス型エンドポイント |
| 別のアカウントの特定のサービスにだけ接続 | PrivateLink（エンドポイントサービス） |
| 拠点と AWS を、すぐに低コストで暗号化してつなぐ | Site-to-Site VPN |
| 大量のデータを安定した帯域・遅延でやり取りする | Direct Connect |
| Direct Connect の経路のまま暗号化する | Direct Connect 上の Site-to-Site VPN（プライベート IP VPN）、または対応する専用接続での MACsec |

## 設計パターン

### エンドポイントでデータの持ち出しを防ぐ

VPC エンドポイントには、そのエンドポイント経由で何ができるかを絞る「エンドポイントポリシー」を付けられます。例えば、S3 のエンドポイントポリシーで自社のバケットだけを許可すると、VPC 内のサーバーから他社のバケットへデータを持ち出せなくなります。反対に、S3 のバケットポリシーで `aws:SourceVpce` 条件を使うと、特定のエンドポイントを通ったアクセスだけを許可できます。

### Direct Connect と VPN の組み合わせ

- **暗号化**: Direct Connect の上に Site-to-Site VPN のトンネルを張ります。プライベート IP VPN を使えば、トランジット VIF の上でプライベート IP アドレスのまま暗号化できます。
- **バックアップ**: Direct Connect を主回線にし、障害時の予備としてインターネット経由の Site-to-Site VPN を用意すると、2 本目の専用回線より安く冗長化できます。

## 試験のポイント

> **試験のポイント**
> 「インターネットを経由せずに AWS のサービスへ」は VPC エンドポイントです。S3 と DynamoDB ならゲートウェイ型（無料）、それ以外のサービスならインターフェイス型を選びます。

> **試験のポイント**
> 「すぐに」「低コストで」拠点とつなぐなら Site-to-Site VPN、「安定した帯域」「一貫したネットワーク性能」なら Direct Connect です。

> **試験のポイント**
> 「Direct Connect の通信を暗号化する」と書かれていたら、Direct Connect 上の VPN か MACsec を探します。

## ひっかけ注意

> **ひっかけ注意**
> ゲートウェイ型エンドポイントは S3 と DynamoDB 専用です。SQS や Secrets Manager などのゲートウェイ型エンドポイントは作れません。

> **ひっかけ注意**
> ゲートウェイ型エンドポイントは、オンプレミスや Transit Gateway 経由では使えません。オンプレミスから S3 にプライベートに接続するときは、インターフェイス型エンドポイントを使います。

> **ひっかけ注意**
> 「専用線だから暗号化されている」は誤りです。Direct Connect は既定では転送中の通信を暗号化しません。

> **ひっかけ注意**
> MACsec はホスト型接続では使えません。ホスト型接続で暗号化するなら、Direct Connect 上の VPN を使います。

> **ひっかけ注意**
> 拠点のネットワーク同士をつなぐのは Site-to-Site VPN です。Client VPN は利用者の端末から接続するためのサービスです。
