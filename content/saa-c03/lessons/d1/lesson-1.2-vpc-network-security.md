AWS でサーバーやデータベースを動かすときは、まず Amazon VPC で自分専用のネットワークを作り、その中に置きます。どのリソースをインターネットから見えるようにし、どの通信を許可するかを VPC の部品で決めることが、ワークロードを守る土台になります。このレッスンでは、サブネットの分け方と、セキュリティグループ・ネットワーク ACL という 2 つのファイアウォールの違いを学びます。

## 基礎

### VPC とサブネット

VPC（Virtual Private Cloud）は、AWS の中に作る論理的に分離された仮想ネットワークです。作るときに IP アドレスの範囲（CIDR ブロック。例 10.0.0.0/16）を決め、その範囲を小さく区切った「サブネット」にリソースを置きます。サブネットはそれぞれ 1 つのアベイラビリティーゾーン（AZ）に属します。

### ルートテーブルで決まるサブネットの性質

サブネットには、通信の行き先を決める「ルートテーブル」を関連付けます。どこへのルートを持つかで、サブネットの性質が決まります。

| 種類 | ルートテーブルの特徴 | 置くもの |
|---|---|---|
| パブリックサブネット | インターネットゲートウェイへの直接のルートがある | インターネット向けのロードバランサー、ゾーン NAT ゲートウェイ |
| プライベートサブネット | インターネットゲートウェイへの直接のルートがない。外へ出るときは NAT ゲートウェイを通る | Web サーバー、アプリケーションサーバー |
| 分離されたサブネット | VPC の外へのルートを持たない | データベース |

- **インターネットゲートウェイ**: VPC とインターネットをつなぐ出入り口です。パブリック IP アドレスを持つリソースは、ここを通ってインターネットと通信します。
- **NAT ゲートウェイ**: プライベートサブネットのリソースが、パブリック IP アドレスを持たずにインターネットへ接続するための仕組みです。内側から始めた通信の応答は戻ってきますが、インターネット側から接続を始めることはできません。AZ ごとにパブリックサブネットに置くゾーン NAT ゲートウェイと、パブリックサブネットが不要で複数の AZ に自動で広がるリージョン NAT ゲートウェイがあります。

### 2 つのファイアウォール

VPC の中の通信は、セキュリティグループとネットワーク ACL の 2 段階で制御できます。

| 項目 | セキュリティグループ | ネットワーク ACL |
|---|---|---|
| 適用する単位 | インスタンスなどのネットワークインターフェイス | サブネット |
| ルール | 許可ルールだけ | 許可ルールと拒否ルール |
| 状態の管理 | ステートフル（許可した通信の応答は自動で許可） | ステートレス（応答の方向にも許可ルールが必要） |
| 評価のしかた | すべてのルールを見て、どれかに当てはまれば許可 | ルール番号の小さい順に見て、最初に当てはまったルールを適用 |
| 作成直後 | インバウンドはルールなし（すべて拒否）、アウトバウンドはすべて許可 | 既定のネットワーク ACL はすべて許可、カスタムのネットワーク ACL はルールを追加するまですべて拒否 |

### エフェメラルポート

利用者のブラウザーが Web サーバーの 443 番ポートに接続するとき、送信元のポートには、利用者の OS が一時的に選んだ番号（エフェメラルポート）が使われます。サーバーからの応答は、このポート宛てに送られます。ネットワーク ACL はステートレスなので、公開サーバーのサブネットでは、アウトバウンドでエフェメラルポートへの通信を許可しておく必要があります。ポートの範囲は OS によって違うため、さまざまなクライアントから接続される場合は 1024〜65535 を許可するのが実用的です。

## 使い分け

基本はセキュリティグループで必要な通信だけを許可し、ネットワーク ACL はサブネット全体にかける補助の防御として使います。

| やりたいこと | 使うもの |
|---|---|
| 特定のサーバーに必要なポートだけを開ける | セキュリティグループ |
| 台数が増減するサーバー群からの通信だけを許可する | 送信元に別のセキュリティグループを指定する（セキュリティグループの参照） |
| 特定の IP アドレス範囲からの通信を明示的に拒否する | ネットワーク ACL の拒否ルール |
| パブリック IP アドレスを持たずに外へ接続する | NAT ゲートウェイ |
| IPv6 で外向きの通信だけを許可する | Egress-Only インターネットゲートウェイ |
| VPC の出入りの通信を、ドメイン名のリストや侵入防止（IPS）のルールで検査する | AWS Network Firewall |
| サーバーに SSH の受信ポートを開けずに管理用の接続をする | AWS Systems Manager Session Manager |

## 設計パターン

### 3 層構成とセキュリティグループの連鎖

Web アプリケーションでは、次のように層ごとにサブネットとセキュリティグループを分けます。

1. **ロードバランサー**: パブリックサブネットに置き、セキュリティグループでインターネットからの HTTPS を許可します。
2. **アプリケーションサーバー**: プライベートサブネットに置き、セキュリティグループでロードバランサーのセキュリティグループからの通信だけを許可します。ロードバランサーはプライベート IP アドレスでターゲットに転送するので、サーバーにパブリック IP アドレスは不要です。
3. **データベース**: 分離されたサブネットに置き、セキュリティグループでアプリケーションサーバーのセキュリティグループからのデータベースのポート（MySQL なら 3306）だけを許可します。

送信元にセキュリティグループを指定すると、そのグループに関連付けたリソースだけが許可されます。Auto Scaling でサーバーが入れ替わって IP アドレスが変わっても、ルールを書き換える必要がありません。

### 管理用の接続

管理のためにインターネットから SSH（22 番ポート）を開けたり、踏み台サーバーを置いたりすると、攻撃の入り口が増えます。Session Manager を使えば、受信ポートを開けず、SSH の鍵も管理せずにサーバーへ接続できます。

## 試験のポイント

> **試験のポイント**
> 「戻りの通信が届かない」「ステートレス」と書かれていたらネットワーク ACL を疑います。応答の方向のエフェメラルポート（1024〜65535）が許可されているかを確認します。

> **試験のポイント**
> 「特定の IP アドレスからの通信を拒否する」は、ネットワーク ACL の拒否ルールで実現します。HTTP のリクエストであれば、AWS WAF の IP セットでも拒否できます。

> **試験のポイント**
> 「サーバーにパブリック IP アドレスを持たせずに、インターネットから更新プログラムを取得する」は、プライベートサブネットと NAT ゲートウェイの組み合わせです。

## ひっかけ注意

> **ひっかけ注意**
> セキュリティグループには拒否ルールがありません。「セキュリティグループで特定の IP アドレスを拒否する」という選択肢は誤りです。

> **ひっかけ注意**
> ネットワーク ACL は番号の小さいルールから順に評価され、最初に当てはまったルールが適用されます。小さい番号で許可した通信は、後ろの番号の拒否ルールでは止まりません。

> **ひっかけ注意**
> ゾーン NAT ゲートウェイは、インターネットゲートウェイへのルートを持つパブリックサブネットに置く必要があります。プライベートサブネットに置いても外へは出られません。

> **ひっかけ注意**
> 内部向けのロードバランサーは、インターネットからは到達できません。公開サイトの入り口には、インターネット向けのロードバランサーを使います。
