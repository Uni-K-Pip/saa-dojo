コンピューティングのコストを下げるには、「必要なときに必要な分だけ使う」ことが基本です。このレッスンでは、負荷に合わせて台数を調整するスケーリング、使い方に合ったコンピューティングサービスの選び方、ロードバランサーの種類、オンプレミスに置く Outposts を学びます。

## 基礎

### 3 種類のスケーリング（EC2 Auto Scaling）

| 方式 | 仕組み | 向く場面 |
|---|---|---|
| ターゲット追跡 | CPU 使用率などを目標値に保つよう、台数を自動で増減する | 負荷の変動が読めない |
| スケジュールに基づく | 日時を指定して、最小・最大・希望の容量を変更する | 負荷の変化する時刻が決まっている |
| 予測スケーリング | 過去のパターンから将来の負荷を予測して、事前に調整する | 周期的なパターンがある |

ターゲット追跡はメトリクスが変化してから動くため、急な増加では遅れが出ます。時刻が決まっている急増は、スケジュールで事前に台数を増やします。

### 水平と垂直

- **水平スケーリング（スケールアウト／イン）**: 台数を増減する。Auto Scaling と相性がよい。
- **垂直スケーリング（スケールアップ／ダウン）**: インスタンスのサイズを変える。変更に停止が必要で、上限もある。

### EC2 の停止・休止・終了

停止するとメモリの内容は失われ、コンピューティング料金は止まります（EBS の料金は続く）。**休止状態（Hibernate）** は、メモリの内容を暗号化されたルート EBS ボリュームに保存して停止し、再開時に復元します。起動後の初期化に時間がかかる開発環境などで、夜間の料金を止めたいときに使います。

## 使い分け

### コンピューティングサービスの選び方

| サービス | 向く処理 | 課金の考え方 |
|---|---|---|
| AWS Lambda | 短時間のイベント駆動の処理（1 回の実行は最大 15 分） | リクエストと実行時間 |
| AWS Fargate | サーバー管理なしでコンテナを実行。Lambda の時間制限を超える処理 | vCPU とメモリを、実行時間に応じて |
| Amazon EC2 | 細かい制御が必要、常時稼働の安定した負荷 | インスタンスの稼働時間（Savings Plans で割引） |

利用が少ない、変動が大きい、短時間の処理ほどサーバーレス（Lambda、Fargate）が割安になります。常に高い使用率で動かし続けるなら、EC2 と Savings Plans のほうが安くなることがあります。

### ロードバランサーの選び方

| 種類 | レイヤー | 特徴 |
|---|---|---|
| Application Load Balancer（ALB） | 7（HTTP／HTTPS） | パス、ホスト名、ヘッダーなどでルーティング。マイクロサービス向き |
| Network Load Balancer（NLB） | 4（TCP／UDP／TLS） | 高い性能と低レイテンシー、固定 IP アドレス |
| Gateway Load Balancer | 3／4 | ファイアウォールなどの仮想アプライアンスにトラフィックを通す |

ロードバランサーは台数に応じた料金がかかります。ALB のルーティングルールで、複数のサービスを 1 つの ALB に統合するとコストを下げられます。

### 必要な可用性とコスト

本番環境は複数のアベイラビリティーゾーンに分散して高い可用性を確保しますが、開発・検証環境は、障害の影響が小さければ、単一のアベイラビリティーゾーンや小さな構成、夜間停止でコストを抑えられます。ワークロードごとに必要な可用性を決めることがコスト最適化の一部です。

## 設計パターン

### エッジとハイブリッド

- **処理を利用者や設備の近くに置く**: レイテンシーを下げる。CloudFront のエッジでの処理、Local Zones、Wavelength など。
- **AWS Outposts**: AWS のインフラを自社の施設に設置して、AWS の API でオンプレミスで EC2 や EBS などを使う。データを施設の外に出せない、設備と低レイテンシーで通信する必要がある場合に使う。

> AWS Snowball Edge は 2025 年 11 月から新規のお客様の受け付けが止まっています。

## 試験のポイント

> **試験のポイント**
> 「負荷の増える時刻が決まっている」ならスケジュールに基づくスケーリング、「負荷が読めない」ならターゲット追跡スケーリングです。両方を併用する設計もよく出ます。

> **試験のポイント**
> 「コンテナ、サーバー管理なし、15 分を超える処理」は Fargate、「短時間のイベント処理」は Lambda です。

> **試験のポイント**
> 「HTTP のパスでサービスを振り分け、ロードバランサーのコストを減らす」は 1 つの ALB に統合します。

## ひっかけ注意

> **ひっかけ注意**
> Lambda の 1 回の実行は最大 15 分です。それ以上かかる処理には使えません。

> **ひっかけ注意**
> 停止（Stop）ではメモリの状態は失われます。メモリの状態を保つなら休止状態です。

> **ひっかけ注意**
> Local Zones は AWS が運営する拠点で、お客様の施設の中ではありません。施設の中に置くなら Outposts です。
