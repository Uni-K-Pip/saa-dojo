コンピューティングのコストは、「何を」「どれだけの期間」「どの料金モデルで」使うかで大きく変わります。このレッスンでは、EC2 の購入オプション、インスタンスの種類とサイズの選び方、コストを管理するツールを学びます。

## 基礎

### EC2 の購入オプション

| 購入オプション | 約束 | 割引の目安 | 向いている用途 |
|---|---|---|---|
| オンデマンド | なし | なし（基準の料金） | 短期、予測できない負荷、初めて動かすワークロード |
| Savings Plans | 1 年または 3 年、1 時間あたりの金額 | 大きい | 安定して使い続ける基礎需要 |
| リザーブドインスタンス | 1 年または 3 年、インスタンスの属性 | 大きい | 属性が固定された安定した基礎需要 |
| Spot インスタンス | なし（中断される） | 最大で約 90% | 中断されても再実行できるバッチ、分析、レンダリング |
| Dedicated Host／Dedicated Instance | — | — | 物理サーバーの専有（ライセンスや規制の要件） |

### Savings Plans の種類

- **Compute Savings Plans**: インスタンスファミリー、サイズ、リージョン、OS が変わっても適用され、Fargate と Lambda にも適用される。柔軟性が最も高い。
- **EC2 Instance Savings Plans**: 特定のリージョンの特定のインスタンスファミリーが対象。割引率はやや高い。

### インスタンスファミリー

| 系統 | 例 | 向いているワークロード |
|---|---|---|
| 汎用 | M 系、T 系 | バランスのよい処理。T 系はバーストが特徴 |
| コンピューティング最適化 | C 系 | CPU を多く使う処理（エンコード、科学技術計算） |
| メモリ最適化 | R 系、X 系 | 大量のメモリを使う処理（インメモリ DB、インメモリ分析） |
| ストレージ最適化 | I 系、D 系 | ローカルストレージの I/O が重要な処理 |
| 高速コンピューティング | P 系、G 系 | GPU を使う処理（機械学習、グラフィックス） |

## 使い分け

### 購入オプションの選び方

1. **基礎となる安定した需要** → Savings Plans（変更の予定があるなら Compute Savings Plans）
2. **変動する部分** → オンデマンド
3. **中断されてもよい処理** → Spot インスタンス（複数のインスタンスタイプとアベイラビリティーゾーンに分散する）

### インスタンスサイズの適正化（ライトサイジング）

使われていないリソースにも料金がかかります。**AWS Compute Optimizer** は、CloudWatch の利用状況のメトリクスを分析して、過剰（または不足）なインスタンスに、より適切なタイプやサイズを推奨します。メモリのメトリクスは、CloudWatch エージェントで収集すると推奨に反映されます。

### コスト管理ツール

| ツール | 役割 |
|---|---|
| AWS Cost Explorer | 過去のコストと利用状況の可視化、将来のコストの予測 |
| AWS Budgets | 予算を設定し、実際または予測値がしきい値を超えたら通知（予算アクションで自動対応も可能） |
| AWS コストと使用状況レポート（CUR） | 最も詳細なデータを S3 に出力して、Athena などで分析 |
| コスト配分タグ | タグ別にコストを集計する。**有効化が必要** |
| AWS Organizations の一括請求 | 複数アカウントの請求をまとめ、利用量を合算してボリューム割引を受ける |

## 設計パターン

- 夜間や休日に使わない開発環境は、停止（またはメモリの状態を保つなら休止状態）にしてコンピューティング料金を止める。
- 組織全体のコストは、管理アカウントでコスト配分タグを有効化し、プロジェクト別・環境別に集計する。
- 予算の超過は Budgets の予測アラートで事前に把握する。

## 試験のポイント

> **試験のポイント**
> 「中断に耐えられる」「再実行できる」バッチ処理は Spot、「今後 1〜3 年は安定して使う、ファミリーやリージョンが変わる可能性がある」は Compute Savings Plans です。

> **試験のポイント**
> 「メモリが足りない、CPU は余っている」はメモリ最適化（R 系）、「CPU が足りない」はコンピューティング最適化（C 系）です。ボトルネックに合うファミリーを選びます。

> **試験のポイント**
> 「予算の超過を通知」は Budgets、「コストの傾向を分析・予測」は Cost Explorer、「詳細データを S3 に出力」は CUR です。

## ひっかけ注意

> **ひっかけ注意**
> タグをリソースに付けただけでは、コストのデータにタグは含まれません。コスト配分タグとして有効化する必要があります。

> **ひっかけ注意**
> 常時稼働の中断できないアプリケーションを、Spot だけで運用するのは不適切です。基礎需要は Savings Plans、変動部分をオンデマンドや Spot にします。

> **ひっかけ注意**
> Cost Explorer には通知の機能がありません。通知は Budgets です。
