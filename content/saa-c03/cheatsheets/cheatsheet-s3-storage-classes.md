Amazon S3 のストレージクラスは、「どのくらいの頻度で読むか」「読みたいときにどのくらい待てるか」「1 つの AZ が失われてもよいか」の 3 点で選びます。詳しい説明はレッスン「S3 ストレージクラスとライフサイクル」を参照してください。

## 比較表

| ストレージクラス | AZ の数 | 最低保存期間 | 取り出し | 向いているデータ |
|---|---|---|---|---|
| S3 Standard | 3 以上 | なし | ミリ秒。取り出し料金なし | 頻繁に読むデータ |
| S3 Intelligent-Tiering | 3 以上 | なし | ミリ秒（オプションのアーカイブ階層は復元が必要）。取り出し料金なし。監視・自動化の料金あり | アクセスの傾向が分からない、変わるデータ |
| S3 Standard-IA | 3 以上 | 30 日 | ミリ秒。取り出し料金あり | 月 1 回程度読む長期保存のデータ |
| S3 One Zone-IA | 1 | 30 日 | ミリ秒。取り出し料金あり | 作り直せるデータ、別のリージョンに複製したコピー |
| S3 Glacier Instant Retrieval | 3 以上 | 90 日 | ミリ秒。取り出し料金あり | 四半期に 1 回程度読むが、読むときはすぐ必要なアーカイブ |
| S3 Glacier Flexible Retrieval | 3 以上 | 90 日 | 復元が必要。迅速 1〜5 分、標準 3〜5 時間、大容量 5〜12 時間 | 年に 1〜2 回読む、待てるアーカイブ |
| S3 Glacier Deep Archive | 3 以上 | 180 日 | 復元が必要。標準 12 時間以内、大容量 48 時間以内 | ほとんど読まない長期保管（法令による保存など） |
| S3 Express One Zone | 1 | なし | 1 桁ミリ秒 | 性能が最優先の処理（ディレクトリバケットを使う） |

- どのクラスも、データの耐久性は 99.999999999%（9 が 11 個）になるように設計されています。
- S3 Standard-IA、S3 One Zone-IA、S3 Glacier Instant Retrieval は、128 KB 未満のオブジェクトも 128 KB として課金されます。

## 選び方の流れ

1. アクセスの傾向が分からない、または変わる → **S3 Intelligent-Tiering**
2. 頻繁に読む → **S3 Standard**
3. あまり読まないが、読むときはすぐ必要
   - 月 1 回程度で、AZ の障害でも失いたくない → **S3 Standard-IA**
   - 作り直せる、または別にコピーがある → **S3 One Zone-IA**
   - 四半期に 1 回程度 → **S3 Glacier Instant Retrieval**
4. 読むまでに数分〜数時間待てる → **S3 Glacier Flexible Retrieval**
5. 12〜48 時間待てる、ほとんど読まない → **S3 Glacier Deep Archive**

## あわせて覚える S3 の機能

| 機能 | 何ができるか | 試験でのキーワード |
|---|---|---|
| ライフサイクルルール | 日数に応じてクラスを移す、期限が来たら削除する | 「30 日後に移す」「7 年後に削除」 |
| バージョニング | 上書きや削除の前のバージョンを残す | 「誤って削除しても戻せる」 |
| S3 Object Lock | 決めた期間、削除や上書きをできなくする（WORM）。コンプライアンスモードでは誰も削除できない | 「改ざん防止」「規制で保存が必要」 |
| レプリケーション | 別のバケットへ自動でコピーする（同じリージョン、または別のリージョン） | 「別のリージョンにもコピー」「災害対策」 |
| S3 Transfer Acceleration | 遠くの利用者からのアップロードを、エッジロケーション経由で速くする | 「世界中からのアップロードが遅い」 |
| マルチパートアップロード | 大きなファイルを分割して並列にアップロードする | 「大きなファイル」「途中で失敗しても再送を少なく」 |
| 署名付き URL | 期限付きで、特定のオブジェクトの読み書きを許す | 「認証なしの利用者に一時的に共有」 |
| S3 ストレージクラス分析 | アクセスの傾向を調べ、移行の目安を示す | 「ライフサイクルルールの日数を決めたい」 |

> **試験のポイント**
> 「アクセスの頻度が予測できない」「運用の手間をかけずにコストを下げたい」なら S3 Intelligent-Tiering です。アクセスの傾向がはっきり決まっているなら、ライフサイクルルールで移します。

> **試験のポイント**
> 「すぐに読めること（ミリ秒）」と「アーカイブの安さ」の両方が必要なら S3 Glacier Instant Retrieval です。S3 Glacier Flexible Retrieval は迅速取り出しでも数分かかります。

## ひっかけ注意

> **ひっかけ注意**
> 最低保存期間より前に削除や移行をすると、残りの日数分の料金がかかります。数日で消す一時ファイルを IA 系や Glacier 系のクラスに置くと、かえって高くなります。

> **ひっかけ注意**
> S3 One Zone-IA と S3 Express One Zone は、1 つの AZ にしか保存しません。「唯一のコピー」「AZ が失われてもデータを失わない」と書かれていたら選べません。

> **ひっかけ注意**
> 小さいオブジェクトが大量にある場合は、IA 系の 128 KB の最小課金サイズや、移行のリクエスト料金で、かえって高くなることがあります。まとめてから保存するか、S3 Standard のままにします。
