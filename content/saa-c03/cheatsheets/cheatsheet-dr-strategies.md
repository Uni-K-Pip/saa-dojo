災害対策（DR: Disaster Recovery）は、「どこまでのデータを失ってよいか（RPO）」と「どのくらいの時間で復旧すればよいか（RTO）」の要件から戦略を選びます。RPO と RTO を小さくするほど、コストは高くなります。

## RPO と RTO

| 用語 | 意味 | 例 |
|---|---|---|
| RPO（目標復旧時点） | 障害の発生から、さかのぼってどの時点までのデータを失ってよいか | RPO 1 時間 = 直近 1 時間分のデータは失ってもよい |
| RTO（目標復旧時間） | 障害の発生から、サービスを再開するまでに許される時間 | RTO 15 分 = 15 分以内にサービスを再開する |

## 4 つの戦略

| 戦略 | 平常時の DR 側 | RPO・RTO の目安 | コスト |
|---|---|---|---|
| バックアップと復元 | バックアップだけを別のリージョンに置く。インフラは障害が起きてから作る | 数時間 | 最も低い |
| パイロットライト | データは常に複製しておく。アプリケーションのサーバーは止めておくか、まだ作らない | 数十分 | 低い |
| ウォームスタンバイ | 規模を小さくした本番と同じ環境を、常に動かしておく | 数分 | 高い |
| マルチサイト（アクティブ/アクティブ） | 複数のリージョンで本番の規模の環境を動かし、どちらでも通信を受ける | ほぼゼロ | 最も高い |

### 戦略ごとの構成の例

- **バックアップと復元**: AWS Backup でバックアップを取り、別のリージョンにコピーします。AWS CloudFormation などのテンプレートで、インフラをすぐに作り直せるようにしておきます。
- **パイロットライト**: データベースを別のリージョンに複製しておき（Aurora Global Database、リージョンをまたぐリードレプリカ、S3 のリージョン間レプリケーションなど）、障害時にアプリケーションのサーバーを起動して規模を広げます。
- **ウォームスタンバイ**: 別のリージョンで小さい構成のまま動かしておき、障害時に Amazon EC2 Auto Scaling で本番の規模まで広げ、Amazon Route 53 で通信を切り替えます。
- **マルチサイト（アクティブ/アクティブ）**: DynamoDB のグローバルテーブルなど、複数のリージョンで書き込めるデータストアを使い、Route 53 で両方のリージョンへ通信を振り分けます。

## 役立つサービス

| サービス | DR での役割 |
|---|---|
| AWS Backup | 複数のサービスのバックアップを、ポリシーで一元的に取り、別のリージョンやアカウントにコピーする |
| AWS Elastic Disaster Recovery | サーバーをブロックの単位で継続的に複製し、障害時に AWS 上ですぐに起動する（RPO は秒単位、RTO は分単位） |
| Amazon Route 53 | ヘルスチェックとフェイルオーバールーティングで、正常なリージョンへ通信を切り替える |
| Aurora Global Database | 別のリージョンへ、通常 1 秒未満の遅延でデータを複製する |
| DynamoDB のグローバルテーブル | 複数のリージョンで読み書きできるテーブル |
| S3 のレプリケーション | オブジェクトを別のリージョンのバケットへ自動でコピーする |
| AWS CloudFormation | インフラをテンプレートから同じ構成で作り直す |

## 選び方

| 問題文の要件 | 選ぶ戦略 |
|---|---|
| 「最もコスト効率が高い」、RPO・RTO が数時間でもよい | バックアップと復元 |
| データは失いたくないが、復旧に数十分かかってもよく、平常時のコストは低く抑えたい | パイロットライト |
| 数分で復旧したい。平常時もある程度のコストは許される | ウォームスタンバイ |
| ダウンタイムもデータの損失もほぼゼロにしたい | マルチサイト（アクティブ/アクティブ） |
| オンプレミスのサーバーを、AWS を DR 先にして守りたい | AWS Elastic Disaster Recovery |

> **試験のポイント**
> 問題文の RPO・RTO の数値を、まず表に当てはめます。「数時間」ならバックアップと復元、「数分」ならウォームスタンバイです。要件を満たす戦略のうち、いちばん安いものを選びます。

## ひっかけ注意

> **ひっかけ注意**
> マルチ AZ の構成は、AZ の障害には強いですが、リージョン全体の障害には備えられません。「リージョンの障害」と書かれていたら、別のリージョンへの複製やバックアップが必要です。

> **ひっかけ注意**
> パイロットライトとウォームスタンバイの違いは、DR 側でアプリケーションが「動いているか」です。パイロットライトはデータの複製だけが動いていて、ウォームスタンバイは小さい規模ですぐに通信を受けられる状態です。

> **ひっかけ注意**
> バックアップを同じリージョンにしか置いていないと、リージョンの障害でバックアップも使えなくなることがあります。別のリージョンにコピーしておきます。
