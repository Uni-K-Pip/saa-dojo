Amazon EC2 の料金は、同じインスタンスでも「どう買うか」で大きく変わります。「どのくらいの期間使うか」「止められても困らないか」「ライセンスやコンプライアンスの制約があるか」で選びます。

## 比較表

| 購入オプション | 割引の目安（オンデマンド比） | 約束（コミットメント） | 向いているワークロード |
|---|---|---|---|
| オンデマンドインスタンス | なし | なし。使った分だけ支払う | 短期間、予測できない、止められない処理。新しいアプリケーションの試行 |
| Compute Savings Plans | 最大 66% | 1 年か 3 年、1 時間あたりの利用額を約束 | 安定した利用。インスタンスファミリー、リージョン、OS を変える可能性がある。AWS Fargate と AWS Lambda にも適用される |
| EC2 Instance Savings Plans | 最大 72% | 1 年か 3 年。リージョンとインスタンスファミリーを決める | 同じリージョンで、同じファミリーを使い続ける安定した利用 |
| スタンダードリザーブドインスタンス | 最大 72% | 1 年か 3 年。インスタンスの属性を決める | 構成が変わらない、常時動く処理 |
| コンバーティブルリザーブドインスタンス | 最大 66% | 1 年か 3 年。別の属性のものと交換できる | 期間中に構成を変える可能性がある |
| スポットインスタンス | 最大 90% | なし。2 分前の通知で中断されることがある | 中断しても再実行できる処理（バッチ、画像処理、CI、ビッグデータ） |
| Dedicated Hosts | — | オンデマンドか予約 | 物理サーバーのソケット数やコア数に紐づくソフトウェアのライセンスを持ち込む（BYOL）。物理サーバーを専有する規制 |
| ハードウェア専有インスタンス（Dedicated Instances） | — | — | 他の AWS アカウントとハードウェアを共有しないことが求められる |
| オンデマンドキャパシティ予約 | なし（Savings Plans などと組み合わせて割引） | 期間の約束なし。予約している間は使わなくても課金される | 特定の AZ で、決まった日に必ずインスタンスを起動したい |

リザーブドインスタンスの支払い方法は、全額前払い、一部前払い、前払いなしから選びます。前払いが多いほど割引が大きくなります。

## 選び方

| 問題文の要件 | 選ぶもの |
|---|---|
| 24 時間 365 日、3 年間同じ構成で動かす | EC2 Instance Savings Plans かスタンダードリザーブドインスタンス |
| 1 年以上使うが、インスタンスファミリーやリージョンを変えるかもしれない。Fargate や Lambda も使う | Compute Savings Plans |
| 夜間のバッチ処理で、途中で止まっても再実行できる | スポットインスタンス |
| 2 週間だけの、止められない処理 | オンデマンドインスタンス |
| 来月のイベントの日に、特定の AZ で確実に台数を確保したい | オンデマンドキャパシティ予約 |
| ソフトウェアのライセンスが物理コアの数で決まる | Dedicated Hosts |
| ふだんの負荷は一定で、ピークだけ増える | ふだんの分を Savings Plans やリザーブドインスタンスで買い、ピークはオンデマンドかスポットで増やす |

## 組み合わせの例

Amazon EC2 Auto Scaling グループでは、オンデマンドインスタンスとスポットインスタンスを混ぜられます（混合インスタンスポリシー）。例えば、最低限の台数はオンデマンドで確保し、それを超える分をスポットにします。スポットは、複数のインスタンスタイプと AZ を指定して、中断されにくくします。

## コストを下げる手順

1. **まず適切なサイズにします。** AWS Compute Optimizer で、使われていない CPU やメモリが多いインスタンスを見つけ、小さいタイプや別のファミリーに変えます。
2. **次に購入オプションを決めます。** AWS Cost Explorer で、Savings Plans とリザーブドインスタンスの購入の推奨と、使用率を確かめます。
3. **使っていない時間は止めます。** 開発環境は夜間や週末に止め、本番は Auto Scaling で負荷に合わせて台数を変えます。

> **試験のポイント**
> 「中断しても問題ない」「再開できる」「柔軟に実行時間を選べる」はスポットインスタンス、「安定」「1 年以上」「常時」は Savings Plans かリザーブドインスタンスです。「短期間」「中断できない」はオンデマンドです。

## ひっかけ注意

> **ひっかけ注意**
> スポットインスタンスは 2 分前の通知で中断されることがあります。データベースのプライマリや、途中で止まると困る処理には使いません。

> **ひっかけ注意**
> Savings Plans とリージョンのリザーブドインスタンスは料金の割引で、キャパシティ（起動できること）は予約しません。特定の AZ でキャパシティを確保したいなら、オンデマンドキャパシティ予約か、AZ を指定したリザーブドインスタンスを使います。

> **ひっかけ注意**
> スタンダードリザーブドインスタンスでは、インスタンスファミリーを途中で変えられません。変える可能性があるなら、コンバーティブルリザーブドインスタンスか Compute Savings Plans です。
