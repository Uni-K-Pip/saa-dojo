# シミュレーター「CIDR とサブネット」の設計書

`visual-materials-design.md` 10.2 の Sim3 を作るための設計です。実装する規則と裏づけ、操作ごとの入力と出力、扱わないこと、シナリオの一覧を決めます。共通の枠（シナリオの形、画面の流れ、検査、記録）は `sims-design.md` にあります。

この文書は設計です。実装が済んだものは `content-guide.md` と `app-spec.md` に移します。

## 1. 学ぶこと

- プレフィックス長とアドレスの数の関係（/ の後ろの数が 1 増えると、アドレスの数は半分）
- VPC とサブネットの大きさには範囲があること
- サブネットでは決まった数のアドレスが予約され、使えるのはその残りであること
- 2 つの範囲が重なるかどうかと、重なると VPC ピアリングを作れないこと
- VPC を AZ と層に分けたとき、全部のサブネットが VPC に入るかどうか

学習コースでは、基礎講座のユニット（U00）の `lesson-basics-ip-subnet-routing` の操作型の教材です（`learning-design.md` 付録 A）。

## 2. シミュレーターの id と置き場所

- id は `cidr`。シナリオは `content/saa-c03/sims/cidr/sim-cidr-<…>.json`、エンジンは `scripts/lib/sims/cidr.mjs`、画面の部品は `app/src/sims/cidr/`。
- 名前は「CIDR とサブネット」。一覧の 1 文は「プレフィックス長を変えて、アドレスの数、予約されるアドレス、範囲の重なりを確かめます」。

## 3. 実装する規則

規則は、エンジンの規則の表（`RULES`。`sims-design.md` 3.5）に 1 つずつ置きます。数値を持つ規則は図鑑の事実を指し、validate が事実の本文に `evidence` の文字列が含まれることと、事実が検証済みであることを確かめます。事実の状態は 2026-11-23 の `catalog-status.json` で確かめました（どれも `verified` で、記録のあとに内容は変わっていない）。

| 規則の id | 内容 | 裏づけ | `evidence`（事実の本文に含まれる文字列） |
|---|---|---|---|
| `address-math` | IPv4 の CIDR `a.b.c.d/n` は、2 の (32 − n) 乗個のアドレスを表す。範囲は、ネットワークアドレスから、それに個数 − 1 を足したアドレスまで。ネットワークアドレスは、先頭の n ビットを残して残りを 0 にしたもの | レッスン `lesson-basics-ip-subnet-routing`（CIDR 表記の節） | — |
| `size-range` | VPC とサブネットの IPv4 CIDR の大きさは /16 から /28 まで。範囲の外は作れない | 事実 `vpc.cidr-size` | `/16`、`/28` |
| `reserved` | サブネットでは、先頭の 4 つと最後の 1 つのアドレスを AWS が予約する（先頭から順に、ネットワークアドレス、VPC ルーター、DNS サーバー、将来用。最後はブロードキャスト用）。使えるアドレスの数は、全体から 5 を引いた数 | 事実 `vpc.subnet-reserved-ips` | `先頭の 4 つと最後の 1 つ`、`5 つ` |
| `no-overlap-in-vpc` | 同じ VPC のサブネットどうしの CIDR は重ねられない | 事実 `vpc.cidr-size` | `重ねられない` |
| `within-vpc` | サブネットの CIDR は、VPC の CIDR の範囲の中から取る | レッスン `lesson-basics-ip-subnet-routing`（VPC とサブネットの節）。図鑑に事実がない（7 章） | — |
| `subnet-one-az` | サブネットは 1 つの AZ に収まる。複数の AZ に置くには、AZ ごとにサブネットを作る | 事実 `vpc.regional-subnet-az` | `1 つのアベイラビリティーゾーン` |
| `overlap-math` | 2 つの CIDR は、「同じ」「片方がもう片方を含む」「離れている」のどれかになる（一部だけ重なることはない）。同じか含むときに重なる | レッスン `lesson-3.4-vpc-design`（重複させない）。計算の性質で、図鑑に事実はない（7 章） | — |
| `peering-overlap` | CIDR が一致または重複する VPC どうしでは、VPC ピアリング接続を作れない | 事実 `vpc.peering-overlap` | `一致または重複` |
| `alb-subnet` | ALB が適切にスケールするには、AZ ごとのサブネットが /27 か、それより大きい範囲（/26 など）で、空きのアドレスが 8 個以上要る | 事実 `elb.alb-subnet-capacity` | `/27`、`8 個以上` |

- 規則の数値（16、28、4 と 1、27、8）は、`RULES` の `value` にだけ書きます。計算の関数は `RULES.<id>.value` を読みます。シナリオの文は `{{rule:size-range}}` のように差し込みます。
- `alb-subnet` の「/27 以上のビットマスク」（事実の文）は、「/27 か、それより大きい範囲」と読みます（プレフィックス長が 27 以下）。公式の資料の原文（at least a /27 bitmask、例 10.0.0.0/27）と合っています。シナリオの文と画面では、取り違えないよう「/27 か、それより大きい範囲（/26 など）」と書きます。
- `alb-subnet` は、事実の本文のとおり「ALB が適切にスケールするための条件」です。予想の問い、選択肢、`albIssue` の画面の文は「スケールするための条件を満たすか」の形にし、「置けない」「作れない」とは書きません（`size-range` の「作れない」とは別の強さ）。

## 4. 操作ごとの入力と出力

`config` の `op` で操作を分けます。どの操作も、アドレスは IPv4 の点で区切った 4 つの数（0〜255）と、`/` と 0〜32 の数で書きます。

### 4.0 入力の検査（3 つの操作に共通）

エンジンの `parseCidr` が、次を入力のエラーにします（計算しない）。シナリオでこのエラーが出るのは validate のエラーです（`sims-design.md` 3.4 の 2）。

| エラー | 条件 | 画面の文（自由に試す） |
|---|---|---|
| `format` | 形が違う（数が 4 つでない、0〜255 の外、`/` がない、プレフィックス長が 0〜32 の外） | 「10.0.0.0/16 のように書いてください」 |
| `ipv6` | `:` を含む | 扱わないこと（6 章）の IPv6 の文 |
| `not-network` | アドレスが、そのプレフィックス長のネットワークアドレスでない（例 10.0.0.5/24） | 「このプレフィックス長の先頭のアドレスは 10.0.0.0 です」と、直した値を入れるボタン |

`not-network` を自動で直さず入力のエラーにするのは、どの範囲を指しているかを、学習者に意識させるためです。AWS がこの入力をどう扱うかは、このシミュレーターでは扱いません。

### 4.1 大きさ（`op: "size"`）: プレフィックス長を動かす

入力:

| 項目 | 形 | 内容 |
|---|---|---|
| `cidr` | 文字列 | 例 `10.0.0.0/24` |
| `role` | `vpc` か `subnet` | VPC として作るか、サブネットとして作るか |
| `purpose` | `alb`（省略できる） | `subnet` のときだけ。ALB を置くサブネットとして確かめる |
| `inUse` | 0 以上の整数（省略できる。既定 0） | `purpose: "alb"` のときだけ。すでに使っているアドレスの数。使えるアドレスの数を超えると入力のエラー |

出力:

| 項目 | 形 | 内容 | 使う規則 |
|---|---|---|---|
| `network`・`first`・`last` | 文字列 | ネットワークアドレス、範囲の最初と最後 | `address-math` |
| `total` | 数 | アドレスの数 | `address-math` |
| `allowed` | 真偽 | その大きさで作れるか | `size-range` |
| `sizeIssue` | `none`・`too-large`・`too-small` | 範囲の外のとき、どちら側か | `size-range` |
| `reserved` | `[{ address, use }]` | `subnet` で `allowed` のときだけ。予約される 5 つのアドレスと用途 | `reserved` |
| `usable` | 数 | `subnet` で `allowed` のときだけ。`total` − 5 | `reserved` |
| `free` | 数 | `purpose: "alb"` のときだけ。`usable` − `inUse` | `reserved` |
| `albIssue` | `none`・`prefix`・`free` | `purpose: "alb"` のときだけ。ALB が適切にスケールするための条件のうち、満たさないもの（両方なら `prefix`）。画面の語は「条件を満たす」「範囲が小さい（/27 か、それより大きい範囲が要る）」「空きのアドレスが少ない（8 個以上が要る）」で、どれも「スケールするための条件」の見出しの下に出す | `alb-subnet` |

`role: "vpc"` では予約を計算しません（予約はサブネットごとのため）。範囲の外（`allowed` が偽）では、予約と使える数を出しません。

画面: プレフィックス長のスライダー（/8〜/32。/16〜/28 の外は帯を灰色にし、「作れない大きさ」と文字で出す）と、アドレスの範囲を表す 1 本の帯。帯の上に最初と最後のアドレス、帯の両端に予約のアドレスの印（5 つ。色と「予約」の文字）、下に「全部 N 個 ／ 使える M 個」。

### 4.2 重なり（`op: "overlap"`）: 2 つの範囲が重なるかを見る

入力:

| 項目 | 形 | 内容 |
|---|---|---|
| `a`・`b` | 文字列 | 2 つの CIDR |
| `context` | `peering` か `subnets` | 2 つの VPC をピアリングでつなぐか、同じ VPC の 2 つのサブネットか |

出力:

| 項目 | 形 | 内容 | 使う規則 |
|---|---|---|---|
| `relation` | `disjoint`・`same`・`a-contains-b`・`b-contains-a` | 2 つの範囲の関係 | `address-math`、`overlap-math` |
| `overlaps` | 真偽 | `relation` が `disjoint` 以外 | `overlap-math` |
| `sharedCount` | 数 | 重なるアドレスの数（重ならなければ 0） | `overlap-math` |
| `peering` | `can`・`cannot` | `context: "peering"` のときだけ | `peering-overlap` |
| `subnets` | `can`・`cannot` | `context: "subnets"` のときだけ | `no-overlap-in-vpc` |

画面: 2 本の帯を同じ目盛りの上に縦に重ねて描き、重なる部分に斜線と「重なり」の文字を付けます。目盛りは 2 つの範囲を合わせた範囲の最初と最後です（広さが大きく違うときは、狭いほうの帯を最小の幅で描き、「実際の幅より広く描いています」と添える）。

### 4.3 分割（`op: "split"`）: VPC を AZ と層に分ける

入力:

| 項目 | 形 | 内容 |
|---|---|---|
| `vpc` | 文字列 | VPC の CIDR |
| `azs` | 1〜4 の整数 | AZ の数。画面では「AZ 1」「AZ 2」と呼ぶ（AZ の名前はアカウントごとに違うため、実在の名前は使わない） |
| `tiers` | `[{ name, kind }]`（1〜3 個） | 層。`name` は 1〜12 字、`kind` は `public`・`private`・`isolated`（入れ物の色と種類の語に使うだけ） |
| `prefix` | 整数 | どの層のサブネットにも使うプレフィックス長 |

割り当ての順: 層の順に、その中で AZ の順に、VPC の先頭から隙間なく割り当てます（どのサブネットも同じ大きさなので、ネットワークアドレスはそろう）。

出力:

| 項目 | 形 | 内容 | 使う規則 |
|---|---|---|---|
| `issue` | `none`・`vpc-size`・`subnet-size`・`subnet-larger`・`not-enough` | 最初に引っかかった条件（VPC の大きさ、サブネットの大きさ、サブネットが VPC より大きい、全部は入らない） | `size-range`、`within-vpc` |
| `fits` | 真偽 | `issue` が `none` | `within-vpc` |
| `needed`・`available` | 数 | 要るアドレスの数（サブネットの数 × 1 つの大きさ）と、VPC のアドレスの数 | `address-math` |
| `remaining` | 数 | `fits` のときだけ。割り当てのあとに残るアドレスの数 | `address-math` |
| `subnets` | `[{ cidr, az, tier, usable }]` | 割り当てたサブネット（`fits` が偽のときは、入った分だけ） | `no-overlap-in-vpc`、`subnet-one-az`、`reserved` |
| `usableTotal` | 数 | `fits` のときだけ。全部のサブネットの使えるアドレスの合計 | `reserved` |

画面: VPC を 1 本の帯にして、割り当てたサブネットを層の色で塗り分けます（どの塊にも「層の名前・AZ 番号」の文字を出す。幅が足りない塊は番号だけにして、下の一覧に対応を出す）。入らなかったサブネットは、帯の外に破線で「入らない」と描きます。下に、サブネットの一覧（CIDR、AZ、層、使える数）。

## 5. 省くこと

- IPv6 の CIDR とサブネット（設計書 10.2）
- セカンダリ CIDR の追加と、追加できる範囲の制限（レッスン `lesson-3.4-vpc-design` に例がある。分割の操作は、VPC に CIDR が 1 つだけの前提）
- VPC に使える範囲かどうか（プライベートアドレスの範囲か、使えない範囲か）の判定
- 複数の CIDR を持つ VPC のピアリング（使わない CIDR だけが重なる場合。事実 `vpc.peering-overlap` の後半）
- 層ごとに違う大きさのサブネット、隙間を空けた割り当て、IPAM
- VPC・サブネットの数の上限（クォータ）、ENI やほかのサービスが実際に使うアドレスの数（ALB の `inUse` は入力した値だけ）
- サブネットの種類を決めるルート（種類の語は層の名前として描くだけ。ルートは Sim2）

## 6. 画面に出す「扱わないこと」の文（`NOT_COVERED`）

1. IPv6 の CIDR とサブネットは扱いません。
2. セカンダリ CIDR の追加と、追加できる範囲の制限は扱いません。
3. その範囲を VPC に使えるか（プライベートアドレスの範囲かなど）は確かめません。
4. サブネットの種類はルートで決まります。ここでは層の名前として扱うだけです。
5. VPC とサブネットの数の上限は扱いません。
6. 使っているアドレスの数は、入力した値だけで数えます。

自由に試すで IPv6 を入れたときは 1 の文を出します。3 の文には、レッスン `lesson-basics-ip-subnet-routing`（プライベート IP アドレスの範囲）へのリンクを添えます。

## 7. 図鑑に事実のない規則

数値を持つ規則は、すべて図鑑の検証済みの事実で裏づけられます。数値を持たない次の 2 つは、図鑑に事実がありません。図鑑には足さず、レッスンで裏づける案にしています。

| 規則 | 今の裏づけ | 足りないもの |
|---|---|---|
| `within-vpc`（サブネットは VPC の範囲の中から取る） | レッスン `lesson-basics-ip-subnet-routing`（「サブネット: VPC のアドレス範囲を小さく分けたもの」） | 図鑑の事実（公式の資料では Subnet CIDR blocks の節）。レッスンの裏づけでよいかの確認 |
| `address-math`・`overlap-math`（アドレスの数と範囲の計算、2 つの CIDR の関係） | レッスン `lesson-basics-ip-subnet-routing`（CIDR 表記）、`lesson-3.4-vpc-design`（重複させない） | AWS の事実ではなく IPv4 の計算の性質。図鑑の事実にしない案。エンジンの単体テストで確かめる |

## 8. シナリオの一覧（5 件。未検証で作る）

文の数値は、規則の値を `{{rule:…}}`、結果の値を `{{out:…}}` で差し込みます。下の表の「予想の答え」と「結果」は、エンジンが出すはずの値で、`expect` に書く値です。

### 8.1 `sim-cidr-reserved-addresses`: 小さなサブネットに何台置けるか

- 状況: 管理用のサーバーを置くために、10.0.0.0/28 のサブネットを作る。サーバーは 1 台ごとにアドレスを 1 つ使う。
- 予想: 「サーバーに割り当てられるアドレスはいくつか」（`usable`。16 個 ／ 15 個 ／ 11 個 ／ 14 個）。答えは 11 個。
- 最初の設定: `{ op: size, role: subnet, cidr: 10.0.0.0/28 }`
- 変えられる設定: `/27 にする`（`total` 32、`usable` 27）、`/24 にする`（`total` 256、`usable` 251）、`/29 にする`（`allowed` 偽、`sizeIssue` `too-small`）
- 裏づけ: 事実 `vpc.subnet-reserved-ips`、`vpc.cidr-size`。レッスン `lesson-basics-ip-subnet-routing`
- 使う規則: `address-math`、`size-range`、`reserved`

### 8.2 `sim-cidr-vpc-size-limits`: どこまで大きな VPC を作れるか

- 状況: 将来の拡張に備えて、できるだけ大きな VPC を 10.0.0.0/12 で作ろうとしている。
- 予想: 「この VPC は作れるか」（`sizeIssue`。作れる ／ 作れない（大きすぎる） ／ 作れない（小さすぎる））。答えは「作れない（大きすぎる）」。
- 最初の設定: `{ op: size, role: vpc, cidr: 10.0.0.0/12 }`
- 変えられる設定: `/16 にする`（`allowed` 真、`total` 65,536）、`/28 にする`（`allowed` 真、`total` 16）、`/29 にする`（`sizeIssue` `too-small`）
- 理由で触れること: 大きさはあとで変えられず、足りなくなったらセカンダリ CIDR を足す
- 裏づけ: 事実 `vpc.cidr-size`、`vpc.cidr-secondary`。レッスン `lesson-3.4-vpc-design`
- 使う規則: `address-math`、`size-range`

### 8.3 `sim-cidr-peering-overlap`: 2 つの VPC をピアリングでつなげるか

- 状況: 10.0.0.0/16 の VPC と、別のチームの 10.0.128.0/17 の VPC を、VPC ピアリングでつなぎたい。
- 予想: 「ピアリング接続を作れるか」（`peering`。作れる ／ 作れない ／ 作れるが、重なる範囲の通信だけ届かない）。答えは「作れない」。3 つめの選択肢は、どの設定でも出ない値（よくある誤解）。
- 最初の設定: `{ op: overlap, context: peering, a: 10.0.0.0/16, b: 10.0.128.0/17 }`（`relation` `a-contains-b`、`sharedCount` 32,768）
- 変えられる設定: `相手を 10.1.0.0/16 にする`（`disjoint`、`can`）、`相手を 10.0.0.0/16 にする`（`same`、`cannot`）、`自分を 10.0.0.0/17 にする`（`disjoint`、`can`。隣り合うが重ならない）
- 裏づけ: 事実 `vpc.peering-overlap`。レッスン `lesson-3.4-hybrid-and-multi-vpc`、`lesson-3.4-vpc-design`
- 使う規則: `address-math`、`overlap-math`、`peering-overlap`

### 8.4 `sim-cidr-three-tier-split`: 2 つの AZ と 3 つの層に分けられるか

- 状況: 10.0.0.0/24 の VPC を、2 つの AZ に、パブリック・アプリ・データの 3 層で分ける。どのサブネットも /26 にしたい。
- 予想: 「6 つのサブネットが VPC に入るか」（`fits`。入る ／ 入らない）。答えは「入らない」（要る 384 個に対して VPC は 256 個）。
- 最初の設定: `{ op: split, vpc: 10.0.0.0/24, azs: 2, tiers: [パブリック public, アプリ private, データ isolated], prefix: 26 }`
- 変えられる設定: `サブネットを /27 にする`（`fits` 真、`remaining` 64）、`VPC を /23 にする`（`fits` 真、`remaining` 128）、`層を 2 つにする`（`fits` 真、`remaining` 0）
- 理由で触れること: 層ごとに AZ の数だけサブネットが要る（サブネットは 1 つの AZ に収まるため）
- 裏づけ: 事実 `vpc.regional-subnet-az`、`vpc.cidr-size`、`vpc.subnet-reserved-ips`。レッスン `lesson-3.4-vpc-design`、`lesson-basics-ip-subnet-routing`
- 使う規則: `address-math`、`size-range`、`within-vpc`、`no-overlap-in-vpc`、`subnet-one-az`、`reserved`

### 8.5 `sim-cidr-alb-subnet`: ALB がスケールするための空きは足りているか

- 状況: ALB を置くパブリックサブネットは 10.0.1.0/27 で、ほかのリソースがすでに 20 個のアドレスを使っている。
- 予想: 「このサブネットは、ALB が適切にスケールするための条件を満たすか」（`albIssue`。満たす ／ 範囲が小さいので満たさない ／ 空きのアドレスが少ないので満たさない）。答えは「空きのアドレスが少ないので満たさない」（使える 27 個のうち空きは 7 個）。
- 最初の設定: `{ op: size, role: subnet, purpose: alb, cidr: 10.0.1.0/27, inUse: 20 }`
- 変えられる設定: `使用中を 19 にする`（`free` 8、`none`。境目）、`使用中を 10 にする`（`free` 17、`none`）、`/26 にする`（`usable` 59、`free` 39、`none`）
- 理由で触れること: 空きが足りないと、スケールの試みが止まり、5xx エラーやタイムアウトにつながることがある（事実の本文の言い方のまま）
- 裏づけ: 事実 `elb.alb-subnet-capacity`、`vpc.subnet-reserved-ips`。レッスン `lesson-3.4-edge-and-load-balancing`（実装のときに、本文がこのシナリオの裏づけになるかを確かめ、ならなければ事実だけにする）
- 使う規則: `address-math`、`size-range`、`reserved`、`alb-subnet`

## 9. エンジンの単体テスト

- `parseCidr`: 形の違い、0〜255 の外、/0 と /32、IPv6、ネットワークアドレスでない入力
- 大きさ: /15・/16・/28・/29（範囲の境目）、/0 と /32 の個数、予約の 5 つのアドレスと用途、`usable`、ALB の境目（/27 と /28、空き 7 と 8）、`inUse` が使える数を超える入力
- 重なり: 同じ、含む（両方向）、隣り合う（重ならない）、離れている、/0 との関係、`sharedCount`
- 分割: ちょうど入る、1 つ足りない、サブネットが VPC より大きい、VPC とサブネットの大きさが範囲の外、割り当てのアドレスの順と重なりがないこと、AZ が 1 と 4
- 規則の表: 計算の関数が規則の値を表から読むこと（値を変えると結果が変わる）、実行の結果の `rules` が使った規則と合うこと

「自由に試す」の結果を守るのはエンジンの単体テストだけなので、境界の値に加えて、範囲を全部なめる性質のテストを置きます（乱数は使わない。決まった並びの入力を全部回す）。

- 大きさ: /0〜/32 の全部で `total` = 2 の (32 − n) 乗、`last` − `first` + 1 = `total`。/16〜/28 の全部で `allowed` が真、`usable` = `total` − 予約の数、予約のアドレスが範囲の先頭 4 つと最後の 1 つ。その外の全部で `allowed` が偽で、`sizeIssue` の向きが合う
- 重なり: 決まった CIDR の組（10.0.0.0/8 から /28 までの、隣り合う・含む・同じ・離れた組を並べたもの）の全部で、a と b を入れ替えると `overlaps`・`sharedCount` が同じで、`relation` の向きだけが入れ替わる。`relation` が `disjoint` のときだけ `sharedCount` が 0
- 分割: VPC /16〜/28、AZ 1〜4、層 1〜3、サブネットのプレフィックス長 /16〜/28 の全部の組で、`fits` のとき、サブネットが互いに重ならず、どれも VPC に収まり、`needed` + `remaining` = `available`、サブネットの数 = AZ の数 × 層の数。`fits` が偽のとき、`issue` が `none` でない

## 10. 決めたこと（設計者の案。利用者は未確認）

- 操作は 3 つ（大きさ、重なり、分割）。分割はどのサブネットも同じ大きさにし、自動で割り当てる（手でサブネットを並べる操作は作らない。幅 360px での入力が重いため）。
- ネットワークアドレスでない入力は直さずに入力のエラーにする（4.0）。
- ALB の条件を大きさの操作に入れ、シナリオを 1 件作る（設計書 10.2 の行にはないが、`elb.alb-subnet-capacity` が予約の数と結びつく試験の論点のため）。
- 数値のない計算の規則は、図鑑の事実ではなくレッスンで裏づける（7 章）。`within-vpc` の事実は、図鑑の手順で後から足す候補にする（この実装では図鑑を変えない）。
- 事実 `elb.alb-subnet-capacity` の「/27 以上のビットマスク」の言い回しは、図鑑では変えず、見直しの候補にする。
