# アプリ仕様（SAA Dojo PWA）

`app/` に置く独立した npm パッケージです（ルートの package.json はコンテンツ用ツールだけを持つ）。コンテンツの形式は `scripts/lib/schema.mjs` と `docs/content-guide.md` を参照してください。

## 1. 技術構成

- Vite + React + TypeScript（strict）。React Router は HashRouter（GitHub Pages のサブパス `/saa-dojo/` で動かすため。`vite.config` の `base` も `/saa-dojo/`）
- IndexedDB は Dexie。オフライン対応は vite-plugin-pwa（アプリ本体と全コンテンツデータを事前キャッシュ、更新があればトーストで再読み込みを促す）
- Markdown 表示は生の HTML を許さない安全な描画（例 react-markdown + remark-gfm、rehype-raw は使わない）
- 間隔反復は ts-fsrs
- テストは Vitest + Testing Library、E2E は Playwright
- UI は日本語、スマホ優先、ダークモード、キーボード操作とフォーカス表示、十分なコントラスト
- 初期表示の JS は gzip 250 KB 以下を目安。データは分割して遅延読み込み

## 2. コンテンツのビルド

`app/scripts/build-content.mjs`（`npm run build` の前に実行）:

1. `../content/saa-c03/**` を読み、ルートの `scripts/lib/schema.mjs` で検証する（失敗したらビルドを止める）
2. `review-status.json` を結合し、`needs-fix` と `rejected` の問題を除く。記録のない問題は `pending` として残し、画面に「未検証」バッジを出す
3. サービス台帳（`services.json`）があれば、問題・レッスン・早見表・カード・用語集の `services` 欄を台帳の正規名にそろえる（同じサービスの別の表記を 1 つにまとめ、演習の条件や弱点分析で別の行にならないようにする）。台帳にない表記はそのまま残す
4. `app/public/data/` に分割 JSON を書く: ドメイン別の演習問題、基礎講座、保留模試 A・B、レッスン一覧と本文、フラッシュカード、用語集、早見表・ガイド、blueprint の要約、サービス台帳の要約（別名を展開したもの）、件数とハッシュを持つ `manifest.json`
5. 保留模試（`mockA`・`mockB`）の問題は演習・ランダム模試・復習に一切出さない

## 3. 画面

| 画面 | 内容 |
|---|---|
| ホーム | 合格準備度（5章）、今日の復習数、試験日から逆算した1日の目標、続きから再開 |
| 基礎講座 | 基礎レッスンと確認問題（AWS 未経験者向け） |
| ロードマップ | ドメイン → タスクごとにレッスンと演習、進捗 |
| レッスン | Markdown、表、囲み記事（`> **試験のポイント**`・`> **ひっかけ注意**` を色付きの枠で表示）、確認問題へのリンク |
| 演習 | 条件（ドメイン、タスク、サービス、判断軸、難易度、未回答、誤答、フラグ）と問題数（10/20/30）を選んで解く |
| 模擬試験 | 65問・130分。ランダム模試（演習プールから未回答を優先）と保留模試 A・B |
| 復習 | 期限が来た概念を出題 |
| 弱点分析 | タスク別・サービス別・判断軸別・誤答理由別の正答率 |
| 判断軸ドリル | 制約語から選ぶべき設計を素早く答える短い問題（問題の `qualifier` と `keyPoints` から生成） |
| フラッシュカード | 間隔反復つき |
| 用語集・早見表・ガイド | 検索つき |
| 設定 | 試験日、1日の目標、テーマ、文字サイズ、書き出し・読み込み、リセット、同期 |
| このアプリについて | 免責事項（非公式で AWS とは無関係、問題はすべて独自作成） |

## 4. 演習と模擬試験

- 選択肢は毎回シャッフルする。`single` はラジオ、`multiple` はチェックボックスで、選ぶ数を表示する
- 回答前に自信度（確信／たぶん／勘）を1タップで選ぶ
- 採点後: 正誤、選択肢ごとの理由、解説、要点、出典リンク、関連レッスン。間違えたら誤答理由（知識不足／読み落とし／2択で迷った／時間切れ）を1タップで記録
- 「ChatGPT に聞く」`https://chatgpt.com/?q=<問題文と選択肢と自分の回答をURLエンコード>`、「Claude に聞く」`https://claude.ai/new?q=<同>`
- 「誤りを報告」は `https://github.com/Uni-K-Pip/saa-dojo/issues/new?title=<問題ID>&body=<問題ID と内容>` を開く
- 模擬試験: 65問（ドメイン1: 20、2: 17、3: 15、4: 13）、130分のタイマー、問題一覧からの移動、見直しフラグ、未回答とフラグの一覧画面、提出、ドメイン別の結果と1問あたりの時間、全問の解説
- 保留模試 A・B は、合格準備度の画面から本人が解放するまでロックする

## 5. 合格準備度

換算スコアは根拠がないので表示しない。次の4条件の達成度を示す。

1. 保留模試 A・B がどちらも初回で80%以上
2. すべてのドメインで、難易度2〜3の初回正答率が70%以上
3. blueprint の項目の90%以上に回答済み
4. 自信度「確信」で間違えた割合が10%以下

あわせてドメイン別の正答率と網羅率を表示する。

## 6. 復習（間隔反復）

- スケジュールの単位は問題ではなく「概念」（blueprint の項目 ID）。同じ概念の別の問題があればそれを出し、丸暗記を防ぐ
- 誤答、または自信度が「勘」の回答で概念のカードを作る。フラッシュカードも同じ仕組み

## 7. データと同期

- 端末内のデータは追記専用のイベントログ（`eventId`=UUID、`deviceId`、時刻、問題 ID、選択、正誤、自信度、誤答理由、モード、所要時間、フラグ、フラッシュカードの評価、設定変更）。統計や復習予定はここから再計算する
- `navigator.storage.persist()` を呼び、週1回の書き出しか同期を促す
- 書き出し・読み込みは JSON ファイル
- 同期（任意）: 設定画面に自分の GitHub 個人アクセストークン（gist 権限のみ）を入れると、シークレット Gist（説明 `saa-dojo sync`）にイベントを改行区切り JSON で保存する（1ファイル 1 MB 以下に分割）。マージはイベント ID の和集合。起動時・学習後・ボタンで同期し、最終同期時刻とエラーを表示する。トークンはこのブラウザの IndexedDB にだけ保存し、api.github.com 以外へは送らない。シークレット Gist は一覧には出ないが暗号化はされないことを画面で説明する

## 8. 公開

`.github/workflows/deploy.yml`: `main` への push で、ルートと `app/` の `npm ci`、`node scripts/validate.mjs`、コンテンツのビルド、テスト、アプリのビルドを行い、GitHub Pages に公開する（`actions/upload-pages-artifact` と `actions/deploy-pages`）。

## 9. テスト

- 単体: 合格準備度の判定、概念単位の復習スケジュール、模擬試験の配分、演習の出題選択、同期のマージ、書き出し・読み込み
- E2E（Playwright）: 演習で1問解く、5問のミニ模試を解いて見直し画面を開く。保留模試はテストで開かない
