# アプリ仕様（SAA Dojo PWA）

`app/` に置く独立した npm パッケージです（ルートの package.json はコンテンツ用ツールだけを持つ）。コンテンツの形式は `scripts/lib/schema.mjs` と `docs/content-guide.md` を参照してください。この文書は実装済みの仕様です。これから足す画面（シミュレーターなど）の設計は `docs/learning-design.md` と `docs/visual-materials-design.md` にあり、実装が済んだものからこの文書に移します。

## 1. 技術構成

- Vite + React + TypeScript（strict）。React Router は HashRouter（GitHub Pages のサブパス `/saa-dojo/` で動かすため。`vite.config` の `base` も `/saa-dojo/`）
- IndexedDB は Dexie。オフライン対応は vite-plugin-pwa（アプリ本体と全コンテンツデータを事前キャッシュ、更新があればトーストで再読み込みを促す）
- Markdown 表示は生の HTML を許さない安全な描画（例 react-markdown + remark-gfm、rehype-raw は使わない）
- 間隔反復は ts-fsrs
- テストは Vitest + Testing Library、E2E は Playwright
- UI は日本語、スマホ優先、ダークモード、キーボード操作とフォーカス表示、十分なコントラスト
- 初期表示の JS は gzip 250 KB 以下を目安。データは分割して遅延読み込み

## 2. コンテンツのビルド

`app/scripts/build-content.mjs`（`npm run build` の前に実行）:

1. `../content/saa-c03/**` を読み、ルートの `scripts/lib/schema.mjs` で検証する（失敗したらビルドを止める）
2. `review-status.json` を結合し、`needs-fix` と `rejected` の問題を除く。記録のない問題は `pending` として残し、画面に「未検証」バッジを出す
3. サービス台帳（`services.json`）があれば、問題・レッスン・早見表・カード・用語集の `services` 欄を台帳の正規名にそろえる（同じサービスの別の表記を 1 つにまとめ、演習の条件や弱点分析で別の行にならないようにする）。台帳にない表記はそのまま残す
4. サービス図鑑（`catalog/**`）を検査し、`catalog-status.json` の検証状態で絞る。`needs-fix`・`rejected` の事実と比較は出さず、エントリ本体がそうならエントリ全体を出さない。記録のない項目と、記録したあとに内容が変わった項目は `pending`（「未検証」バッジ）。参照切れ（存在しない事実・サービスなど）はビルドを止める。`catalog-needs.json`（監査の不足と保留模試の問題 ID）は検査だけ行い、出力しない
5. `app/public/data/` に分割 JSON を書く: ドメイン別の演習問題、基礎講座、保留模試 A・B、レッスン一覧と本文、フラッシュカード、用語集、早見表・ガイド、blueprint の要約、サービス台帳の要約（別名を展開したもの）、図鑑の索引（`catalog-index`。台帳の全サービスと、エントリ・事実の見出し・関連する教材の件数）、エントリごとの詳細（`catalog/<id>`）、比較（`catalog-compare`）、件数とハッシュを持つ `manifest.json`
6. 保留模試（`mockA`・`mockB`）の問題は演習・ランダム模試・復習に一切出さない
7. 学習コース（`course.json`）があれば検査し（`scripts/lib/course.mjs`。検査のエラーは、`content-guide.md` 15 章に挙げたものすべてがビルドを止める。ユニット演習の候補は、要修正・却下を除いた問題で数える）、`course` に書く。ユニットごとに、ユニット演習の候補（`practiceIds`）を出題できる問題から求めて持たせる
8. 図（`diagrams/*.json`）を検査し（validate と同じ `scripts/lib/diagram.mjs`）、レイアウトを済ませた図（scene）を 1 枚ずつ `diagrams/<id>`（manifest のキーは `diagram:<id>`）に、一覧を `diagram-index` に書く。構成図は部品・入れ物・線・段階の座標、ほかの 4 種類は描く形（矩形・線・丸・文字）の一覧を持つ。図の検査のエラーと、本文の図の参照の切れはビルドを止める。レッスン・早見表・ガイドの本文ごとに、行単位の検査（`parseInlineChecks`・`parseDiagramRefs`）が通したその場の確認と図の参照を、表示と同じ remark の解析の判定と突き合わせ、ずれがあれば文書名と行を出してビルドを止める。あわせて、確認にならない引用の中のタスクリストと、確認の外の「その場の確認」の見出しに見えるもの（見出しと、段落の先頭の強調）も止める（正解の印が見えるのを防ぐ）。`material-status.json` の検証状態で絞る（判定は validate と同じ `scripts/lib/material-status.mjs`。記録のない図と、記録したあとに内容が変わった図は `pending`）。既定では `verified` の図だけを出す。`--include-unverified`（`npm run dev` が付ける。`npm run content`・`npm run build`・CI・公開は付けない）のときは `pending` の図も「未検証」バッジつきで出す。`needs-fix`・`rejected` の図はどちらでも出さない。除く図にも検査はすべてかけ、除いた図を本文が指していてもビルドは止めない（文書名・行・図の id を警告に出す）。除いた図の数を状態ごとに出力に表示し、`manifest.json` の `counts.diagrams` は出した図の数、`counts.diagramsExcluded` は除いた数
9. 実物（`artifacts/*.json`）を検査し（validate と同じ `scripts/lib/artifact.mjs`）、表示用に整えたもの（`json` は整形した行、`table` は表の行、`text` は行。どれも注目点の番号を付ける）を 1 件ずつ `artifacts/<id>`（manifest のキーは `artifact:<id>`）に、一覧を `artifact-index` に書く。検査のエラーと、本文の実物の参照の切れはビルドを止める。検証状態での絞り込み、除いた実物を本文が指すときの警告、`manifest.json` の件数（`counts.artifacts`・`counts.artifactsExcluded`）は図と同じ。除いたものを本文がリンクで指すときの警告は、リンクを開くと「見つかりません」になることを出す
10. ミニラボ（`labs/*.md`）と設計パターン（`patterns/*.md`）を検査し（validate と同じ `scripts/lib/lab-pattern.mjs`。front matter のスキーマ、固定の見出しと順、手順の番号、`diagram` の図）、本文の図・実物の参照とその場の確認にはレッスンと同じ検査と突き合わせをかける。見出しは、行単位の検査の読み方と、表示と同じ remark の解析の読み方を突き合わせ、ずれがあれば文書名と行を出してビルドを止める。検証状態での絞り込みは図と同じ（区分 `labs`・`patterns`。既定は検証済みだけ、`--include-unverified` で未検証も「未検証」バッジつき、`needs-fix`・`rejected` は出さない）。一覧を `lab-index`・`pattern-index`（題、ユニットかタスク、サービス、判断軸、`diagram`、状態、本文が挙げる出題できる問題の ID）に、本文を 1 件ずつ `labs/<id>`・`patterns/<id>`（manifest のキーは `lab:<id>`・`pattern:<id>`）に書く。`manifest.json` の件数は `counts.labs`・`counts.labsExcluded`・`counts.patterns`・`counts.patternsExcluded`。学習コースのユニットの項目からは、そのビルドで出さないミニラボ・設計パターンを省く

## 4. 演習と模擬試験

- 選択肢は毎回シャッフルする。`single` はラジオ、`multiple` はチェックボックスで、選ぶ数を表示する
- 回答前に自信度（確信／たぶん／勘）を1タップで選ぶ
- 採点後: 正誤、選択肢ごとの理由、解説、要点、出典リンク、関連レッスン、サービス図鑑（問題のサービスのエントリと、問題の `factRefs` の事実へのリンク）。間違えたら誤答理由（知識不足／読み落とし／2択で迷った／時間切れ）を1タップで記録
- 「ChatGPT に聞く」`https://chatgpt.com/?q=<問題文と選択肢と自分の回答をURLエンコード>`、「Claude に聞く」`https://claude.ai/new?q=<同>`
- 「誤りを報告」は `https://github.com/Uni-K-Pip/saa-dojo/issues/new?title=<問題ID>&body=<問題ID と内容>` を開く
- 模擬試験: 65問（ドメイン1: 20、2: 17、3: 15、4: 13）、130分のタイマー、問題一覧からの移動、見直しフラグ、未回答とフラグの一覧画面、提出、ドメイン別の結果と1問あたりの時間、全問の解説
- 保留模試 A・B は、合格準備度の画面から本人が解放するまでロックする
- ユニット演習（学習コースのユニットから開く）: そのユニットのレッスンの `knowledgeRefs` と重なる問題（演習・基礎講座。保留模試は除く）から、未回答 → 前回誤答 → 古い順に 10 問（候補が 15 問以上なら 15 問も選べる。10 問未満なら全部）。回答はモード `unit` で記録し、ほかの演習と同じく合格準備度と復習に入る

## 5. 合格準備度

換算スコアは根拠がないので表示しない。次の4条件の達成度を示す。

1. 保留模試 A・B がどちらも初回で80%以上
2. すべてのドメインで、難易度2〜3の初回正答率が70%以上
3. blueprint の項目の90%以上に回答済み
4. 自信度「確信」で間違えた割合が10%以下

あわせてドメイン別の正答率と網羅率を表示する。

## 6. 復習（間隔反復）

- スケジュールの単位は問題ではなく「概念」（blueprint の項目 ID）。同じ概念の別の問題があればそれを出し、丸暗記を防ぐ
- 誤答、または自信度が「勘」の回答で概念のカードを作る。フラッシュカードも同じ仕組み

## 7. データと同期

- 端末内のデータは追記専用のイベントログ（`eventId`=UUID、`deviceId`、時刻、問題 ID、選択、正誤、自信度、誤答理由、モード、所要時間、フラグ、フラッシュカードの評価、設定変更、レッスンと図鑑のエントリの読了）。統計や復習予定はここから再計算する。図鑑の読了（`catalog-read`）は一覧の未読の絞り込みと読了バッジにだけ使い、合格準備度には使わない
- レッスンのその場の確認の回答は `check-answer`（`lessonId`、`checkId`（問いの文を validate と同じく正規化した文（リンク・強調・取り消し線・HTML を外し、空白をそろえる）の FNV-1a ハッシュ。`c` と 16 進 8 桁）、`choice`（選んだ選択肢の番号。1 から）、`correct`）として記録する。合格準備度、復習の予定、弱点分析には使わない（早見表・ガイドの確認は表示だけで記録しない）。問いの文を直すと `checkId` が変わり、前の記録とはつながらない。選択肢の順を入れ替えると `checkId` は同じまま `choice` の意味が変わる。このため、記録を使うとき（読み直しの候補。まだ作っていない）は、今の本文にない `checkId` の記録は使わず、正誤は `correct` を正として `choice` は参考にとどめる。同じ文書の中で問いの文が重なる確認は validate のエラーにする
- ミニラボと設計パターンの読了は `lab-read`（`labId`）・`pattern-read`（`patternId`）として記録する。コースの進み具合と、一覧の読了の札にだけ使い、合格準備度と復習の予定には使わない
- 学習コースの進み具合はイベントログから求める。レッスンは読了、ミニラボ・設計パターンは `lab-read`・`pattern-read` の記録、ユニット演習はそのユニットの候補のうち回答済みが 10 問以上（候補が 10 問未満なら全部。候補が 0 問なら済みにしない）、模擬試験はその種類の 65 問の結果（1 問以上回答したもの。合格準備度が初回として数える条件と同じ）、判断軸ドリルは 1 回以上、早見表・ガイド・弱点分析は「済みにする」の記録（`course-check`。ユニットと項目ごとに最後の操作が勝つ）で済みとする。進み具合は合格準備度と復習の予定には使わない
- `navigator.storage.persist()` を呼び、週1回の書き出しか同期を促す
- 書き出し・読み込みは JSON ファイル
- 同期（任意）: 設定画面に自分の GitHub 個人アクセストークン（gist 権限のみ）を入れると、シークレット Gist（説明 `saa-dojo sync`）にイベントを改行区切り JSON で保存する（1ファイル 1 MB 以下に分割）。マージはイベント ID の和集合。起動時・学習後・ボタンで同期し、最終同期時刻とエラーを表示する。トークンはこのブラウザの IndexedDB にだけ保存し、api.github.com 以外へは送らない。シークレット Gist は一覧には出ないが暗号化はされないことを画面で説明する

## 8. 公開

`.github/workflows/deploy.yml`: `main` への push で、ルートと `app/` の `npm ci`、`node scripts/validate.mjs`、コンテンツのビルド、テスト、アプリのビルドを行い、GitHub Pages に公開する（`actions/upload-pages-artifact` と `actions/deploy-pages`）。

## 9. テスト

- 単体: 合格準備度の判定、概念単位の復習スケジュール、模擬試験の配分、演習の出題選択、同期のマージ、書き出し・読み込み、学習コース（検査、ユニット演習の候補に保留模試が入らないこと、済みの判定、次にやること）
- E2E（Playwright）: 演習で1問解く、5問のミニ模試を解いて見直し画面を開く。保留模試はテストで開かない
